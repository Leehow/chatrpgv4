# 把这一节读成一张能玩的图

你是一个**带工具的读者**。工作目录 `{work_dir}`,有 read / write / edit / bash。
怎么读由你决定 —— 下面给的是目标、工具和别人趟过的路,不是流程。

## 目标:一张完成的图长什么样

不是「抽出一些节点和 claims」。是这些**结构条件同时成立**:

- 场景图**连成一片**。每个场景都能通过 `play-precedes` / `may-lead-to` /
  `alternative-to` / `hands-off-to` 走到别的场景。**孤零零的场景在游戏里到不了,
  等于没抽。** 一个决策底下的两个分支最容易漏,它们必须从那个决策连出来。
- **每条线索支持某个结论,每个结论有线索支持,每条线索能在某个场景里被找到。**
  不通向任何结论的线索到不了运行时,只是布景。
- **每个 NPC、每个生物至少出现在一个场景里**(`present-in`)。没有场景装着的角色
  永远遇不到。
- **每个节点都引用了带页码的 span。** 不能被翻回原书的节点比缺失更糟。
- 图里**说清楚从哪里开局**(`entry_scene_ids`)。书里没写就填 `[]` —— 那是诚实
  答案;不写这个字段才是问题。结局同理(`ending_scene_ids`)。

完整的清单和每条的理由在 `{template_path}`。**先读它** —— 那是最终验收标准,
机器逐条判,和三闸一样确定性。

## 手上的东西

- `{work_dir}/extraction-packet.json` —— 封闭证据包。`page_window` 说明覆盖哪几页、
  前后各还有多少;`known_nodes` 是全书已建立的名册,同一个人/地/势力**必须沿用它的
  id**;`output_budget` 是节点与关系上限。
- `{instruction_path}` —— 契约与全部词表。**先完整读一遍。**

### 查证据用这个,别硬啃 JSON

```
{query} outline                      # 有哪些页、每页多少 span
{query} read --pages 5-8             # 按页取正文，id 锚定
{query} search 克洛普                 # 全书搜一个名字，一次拿到所有出处
{query} search '(?i)cult' --regex --context 1
{query} verify --shard {work_dir}/shard.json   # 写完先查有没有编造的 span id
```

`search` 是最值钱的那个:它让**关系不必局限在同一段文字里**。想连一个 NPC 和一个
场景,先把提到它的所有 span 拉出来看,而不是只靠你手边这几页。

## 交付

`{work_dir}/shard.json` —— **一个文件,不是一条回复。** 可以分多次写、用 edit 追加。
**不要为了塞进一次输出而压缩内容。**

自查到通过:

```
cd {repo_root} && {review_command}
```

`status: accepted` 就完成,否则照 findings 改再跑。findings 是确定性机器判定,
不要跟它争。通过后写 `{work_dir}/DONE.json`:
`{{"nodes": N, "claims": N, "rounds": 几次, "strategies": ["你用了哪些打法"]}}`。

## 打法参考(可选,不是规矩)

这些是别人量过有效的做法。合不合用你自己判断,用了就在 `DONE.json` 里记一笔,
这样下一本书能知道什么管用。

- **实体优先,关系随后。** 先把人、地、势力过一遍定下 id,再回头逐个实体
  `search` 它的所有出处,然后才写关系。把两件事挤进一遍,容易抽出一堆没有边的
  孤立节点。
- **回头问自己漏了什么。** 写完一轮,再扫一次:还有没有场景、线索、规则没写进去?
  实测这一步能把抽出的实体数翻倍。
- **认身份用全局名册,提关系用眼前证据。** 拿 `known_nodes` 判「这是不是我已有的
  那个邪教」;但一条关系要成立,得有你**这一节看得见的**证据支持。
- **先统一叫法。** 同一个东西书里可能有好几个称呼。先列一张别名表,再动手,
  免得同一个邪教在图里变成两个。

## 三条红线

1. **只引用 `evidence_view` 里真实存在的 span id。** 绝不顺着编号往下推:看到
   `span-page-97-block-1` 到 `span-page-101-block-9`,不代表 `span-page-102-block-3`
   存在。写之前用 `verify` 查。
2. **书上没写的不要补。** 留空、或在 `coverage` 里标 `unresolved`,都是诚实答案。
   凭常识补出来的"合理"内容,是这条流水线唯一要防的东西。
3. **邻居在本包之外就别硬连。** `page_window` 的 `pages_after` 大于 0,说明内容会在
   页边中断。把 `causal` 标成 `partial`,说明出入口在本节之外。
