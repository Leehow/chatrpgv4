# TypeScript kernel foundation

This is the selectable migration backend from contract section 27. The production
default remains Python. The foundation, campaign creation/opening, player input,
ask/narrate transactions, existing-campaign read projections and rule/catalog
queries are implemented. The writer preserves replay, recovery and Git identity;
unsupported source/library/Mod/worldline contributions still refuse new writes.
Other current public methods return
`not_implemented`; undeclared names return
`unknown_method` with the same method vocabulary as Python. There is no Python
fallback, embedded interpreter, game simulation or second state store.

The integration owner builds `rpc.ts` as `build/kernel/rpc.mjs`, with an ESM Node
bundle and any native dependencies external to the bundle. Its arguments remain
`--workspace <path> --content <path>`. The entry validates roots, consumes UTF-8
JSONL serially, awaits response writes and drains pending requests before EOF exit.
Only response frames go to stdout. Tests exercise the actual executable from a
different working directory and paths containing spaces.

## Static interfaces and ownership

| File | Responsibility |
| --- | --- |
| `context.ts` | Frozen owner-local paths, read capabilities, lock capability and RNG capability. No campaign cache or mutable configuration. |
| `handlers.ts` | `KernelHandler`, `HandlerGroup`, the closed Python method vocabulary and one startup assembly function. Duplicate or undeclared contributions fail. The common campaign lock wrapper lives here. |
| `registry.ts` | Integration-owned imports and final static handler assembly. Later slices contribute `createSliceHandlers(context): HandlerGroup` from their own files; only the integration owner adds the group here. |
| `read/` | Existing-campaign read projections and the shared pure rule facts/conditions; no transaction or subsystem writers. |
| `git.ts` | Captured sidecar Git command, blob/root reads, cancellation and subprocess cleanup. |
| `transactions.ts` | Static campaign I/O and turn/settlement writer contracts for later domain contributions. |
| `write/` | Campaign/turn I/O, replay, continuation, ordered Git commits and current required contributions. |
| `rules/` | Tables, catalog, skills, optional-rule reads, immutable RuleGraph plans and rule/catalog queries; family execution follows in later slices. |
| `transport.ts` | Request validation, error envelopes, UTF-8 framing, serial dispatch and writes. Domain slices do not edit this file. |
| `snapshots.ts` | Fresh immutable JSON/JSONL reads and path listing. Imports no writer, settlement machinery or unfinished domain implementation. |
| `json.ts` | Python number representation, canonical/stored encodings and digest identity. All domain slices reuse it. |
| `random.ts` | Python-compatible seed expansion and the sampling operations used by current engines. |
| `fileio.ts` | Atomic file replacement, synced JSONL append/truncate and file hashing. Callers still own transaction and publication locks. |
| `locks.ts` | Descriptor-owned advisory lock lifetime over an explicitly supplied native `flock` operation. |

Context immutability means its wiring cannot change. Its RNG capability has
private mutable sampling state, just as the existing owner-local Python RNG does.
Disk snapshots remain the authority. This slice does not introduce a settlement
pipeline; later rule slices must retain the existing resolve/apply transaction
contract and contribute their own handlers through the static seam.

## Numeric compatibility boundary

`JSON.parse` and `JSON.stringify` are unsuitable for identity-bearing Python state.
They erase `1` versus `1.0`, round large integers, render exponents differently,
discard negative zero and reorder integer-looking object keys.

`parsePythonJson` keeps safe Python integers as numbers, larger integers as bigint,
and every Python float as `PythonFloat`. It retains source dict insertion order,
including duplicate-key replacement without moving the original key. Canonical
encoding sorts string keys by Unicode code point, not UTF-16 code unit. The float
formatter derives the exact IEEE-754 rational, selects the closest shortest
round-trip decimal with ties to even, and applies Python's decimal/exponent rules.
`storedJson` uses Python's two-space indentation and final newline. JSONL uses
Python's ordinary comma/colon spacing. Python's default nonfinite spellings
(`NaN`, `Infinity`, `-Infinity`) are retained; they are not standard JSON.

The unavoidable input boundary is explicit:

- For values created in TypeScript, safe integer numbers mean Python `int`.
  Use `new PythonFloat(1)` for a Python `1.0` and bigint for a large Python int.
  Unsafe integer numbers are rejected; the helper cannot recover bits or a type
  that the caller already discarded.
- Float arithmetic must be deliberately rewrapped as `PythonFloat` before a
  digest or write. Ordinary JS arithmetic, object spreading of a float wrapper,
  JSON cloning and `structuredClone` cannot preserve Python scalar identity.
  `PythonFloat.toJSON` fails rather than silently emitting the wrong JSON shape.
- Preserve parsed immutable snapshots or create new ordered objects with
  `orderedObject(entries)` when stored insertion order matters. A plain JS object
  cannot disclose the original insertion order of its integer-looking keys. Do
  not delete/reinsert keys on an ordered object and assume its old order metadata
  describes a Python dict mutation; construct a fresh ordered object instead.
- These helpers support JSON string keys and scalar/container values, not every
  Python object accepted by optional `json.dumps` encoder arguments. Unpaired
  surrogates cannot be encoded or hashed as UTF-8; they fail explicitly.

The focused reference suite verifies current numeric boundaries and 512 sampled
IEEE-754 bit patterns. It is not a claim that arbitrary JS domain arithmetic has
become Python arithmetic. Domain migration must preserve explicit scalar types.

## Random compatibility boundary

`PythonRandom` implements CPython version-2 string seeds (UTF-8 plus SHA-512),
integer seeds using all absolute-value bits, MT19937, `random`, `getrandbits`,
rejection-based `randbelow`, `randrange`, `randint`, `choice` and in-place `shuffle`.
Number arguments are restricted to safe integers; bigint covers Python's larger
integer seeds and ranges. `getrandbits` always returns bigint. The string seed
`"0"` remains distinct from integer `0`. Reseeding retains the Python sequence.

No byte/float seeds, version-1 seeds, distribution methods or state serialization
are exposed: current engine call sites do not use them. Unseeded construction uses
OS entropy to initialize 624 words; it cannot be replayed against an independently
unseeded Python process. Worldline turn-seed strings are covered by generated
reference vectors; worldline branching itself is a later domain slice.

## File and lock compatibility boundary

Atomic writes use an exclusive 0600 temporary file in the destination directory,
write all UTF-8 bytes, fsync, close and rename over the target. Error cleanup only
removes the temporary file created by this call. The destination and unrelated
evidence are preserved. Like Python `fileio.py`, this does not fsync the parent
directory, add a transaction journal or make a batch of writes atomic. JSONL
append/truncate sync their file descriptors; cross-process serialization belongs
to the caller's advisory lock.

The native seam is:

```ts
type Flock = (fd: number, operation: "sh" | "ex" | "shnb" | "exnb" | "un") => Promise<void>;
createAdvisoryLocks(flock).acquire(path, "shared" | "exclusive", {
  nonblocking?: boolean,
  createParents?: boolean,
}): Promise<LockLease | null>;
```

The wrapper opens the existing lock inode with `a+`, closes descriptors on failed
acquisition, returns `null` only for nonblocking `EAGAIN`/`EWOULDBLOCK`, and releases
exactly once on `lease.release()`. It never unlinks lock files. A missing native
capability fails before creating a lock directory/file. `native-locks.ts` binds
`fs-ext` at the RPC entrypoint. Real Python/TypeScript contention tests verify
shared/exclusive interoperation, release after process death, and filesystem
progress with more waiters than the default Node thread pool. The addon must be
rebuilt for the managed Node ABI at packaging time; it is not an interpreter.
Unit tests with an injected descriptor operation verify lifecycle only.

## Verification and precedent

Regenerate reference evidence only with the locked interpreter:

```sh
uv run --frozen python kernel-ts/testing/generate_reference.py
node --test tests/extension/ts-kernel-foundation.test.mjs
```

The generator records Python 3.14.6 outputs, including 22 seed forms, 2,000-word
streams per seed, 13 JSON cases, 512 float bit patterns, actual hello/list results
and current malformed-request envelopes. It is test tooling, absent from the
product import graph. None of these tests constitute COC gameplay acceptance.

Implementation was checked against [CPython's random implementation](https://github.com/python/cpython/blob/3.14/Modules/_randommodule.c)
and [its documented seed semantics](https://docs.python.org/3/library/random.html).
The standard algorithms confirm that matching MT19937 alone is insufficient: seed
expansion and rejected draws affect every later result. [ECMAScript number formatting](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-numeric-types-number-tostring)
has different representation rules, which is why canonical hashing uses explicit
Python numeric types. [Node file APIs](https://nodejs.org/api/fs.html) provide the
descriptor sync and same-filesystem rename operations needed by Python's atomic
writer, but not the `flock` operation; a packaged native capability is required.
