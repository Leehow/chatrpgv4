# 12 — Testing and evaluation

**TST-001.** Deterministic rule Oracle tests pass exactly; subjective judging cannot override mechanics, secrecy, state, or replay failures.

Tests cover idempotency, branch conflicts, stale decisions, push limits, HP/SAN bounds, temporal epochs, graph visibility, narration non-mutation, compiler provenance, clue reachability, and rule conflicts.

Every evaluated turn stores input, context, plan, validation, rule and RNG receipts, event batch, state hashes, narrative frame, draft, verification, final text, model receipts, and timing.

Hard release gates: zero secret leaks, partial commits, duplicate resolution, replay mismatch, unbound critical fact, and unexplained time rewind. Rule accuracy, module fidelity, agency, coherence, prose, pacing, latency, and cost remain separate dimensions.
