# Wide semantic preflight: recorded component experiment

Date: 2026-09-21. **Static source-answering prototype, not true-table or production acceptance.** Production paths were not changed.

## Question and bounded answer

Can Jev select broadly over the material universe before the first LLM request, so the LLM mostly writes instead of searching?

The recorded run supports that direction within this small experiment. All predeclared positive page-level requirements were present in the top five pages. In the three paired reader probes, the preflight readers obtained **no new pages outside their initial packets**. Two readers nevertheless reread an already supplied page; one answered in a single model round without tools. Fewer model rounds did not guarantee a faster individual answer.

This is not a population recall estimate. The query set is authored, uses one native-text PDF, and includes two paraphrases of one clinic query. The gold requirements do not exhaust every possible useful fact. In particular, the heat query's frozen labels cover pages 90/93 but do not separately require the important heat-exhaustion/heatstroke procedures on page 92. Jev actually ranked page 92 first at every tested concurrency and supplied it. Do not silently amend the frozen labels or present 27/27 as exhaustive answer correctness.

## Wide Jev selection

- Original PDF: 111 physical pages; 100 substantive native-text pages and 11 explicit sparse/visual gaps.
- 13 frozen diagnostic queries: 7 retained cases, 6 independently authored cases. Eleven have labeled positive evidence; MRI and town-map controls are not counted as positive recall cases.
- Each query independently scans the whole usable corpus: 16 bounded HTTP requests, 200 independent Noul questions.
- Two Nouls per page: direct evidence for at least one requested part, and materially useful context. No keyword-based semantic prefilter, graph restriction, generated summary, or gold pages are sent.
- HTTP concurrency 1/4/16, one repetition; query and arm order are serial, concurrency order rotates. Top-5/10/15 packets are exact native-source copies.
- 39 arms, **624 successful requests, 7,800 questions, zero HTTP/protocol failures**.

## Matched, tool-enabled LLM readers

Both arms used cold Pi sessions, `grok-build/grok-4.6`, low thinking configuration, the same system prompt, the same full native-source index, and the same read/write/edit/bash tools. Only the Grok provider extension was loaded; no COC kernel, campaign, player script, session history, skills, or project context files were loaded. The preflight arm received the complete preselected packet **inside its first prompt**. Readers retained the ability to ignore it and read more.

Three cases and c16/r1/top10 were fixed before live results. Reader order alternated. All six readers ended successfully. Actual JSONL `tool_execution_start/end` and final assistant `message_end` usage were parsed; all source access was auditable, with no bash source reads or outside-cwd reads.

The two preflight read calls both reopened page 32, which was already included in their respective packets. They are real tool calls, but not evidence of missing preflight material. The heat answer is a concrete one-model-round/no-tool result. The paired totals improved by about 9%, not 7.7x: fast retrieval is only one part of the workflow. The heat case is retained as an adverse timing result despite its reduced model-round count. Generation, context processing, provider variability and cache usage were not independently controlled enough to attribute that difference to one cause.

Reader cost is not inferred from Jev's price. Per-role input/output/cache-read usage is retained separately; no whole-workflow dollar saving is claimed.

## Answer-quality boundary

Independent source-fidelity review (`.pi/findings/jev-answer-quality.md`) checked all six answers against actual source pages. It found the requested operating hours, medical details and environmental-rule numbers consistent with the source, with no invented MRI model, appointment process or price. It independently confirmed the gold omission of page 92. The preflight heat answer additionally uses the real despair rules on page 89 but omits page 89 from its final source-coverage note: that is a retained citation defect, not a corrected output.

The main session takes a narrower conclusion than a blanket perfect-answer label. The preflight MRI answer's connection between the 1970s setting and modern MRI service is an extra inference, not a source proof of absence. Opening phrases such as “none” must be read with the answers' limited-source coverage statements; they are not accepted as exhaustive whole-book findings. Key source-supported facts are correct, but not every sentence is certified. The documents contain Keeper-private content; these probes explicitly answered source-research questions, so they prove no player-facing disclosure policy.

A separate harness review (`.pi/findings/jev-reader-review.md`) confirmed first-request injection, matched conditions, gold isolation and actual-event accounting. Its two completion-gate warnings were fixed: truncated/deferred stops and unauditable source access cannot count as completed answers. Rechecking the original six event streams under the stricter gate leaves all six usable; no model output or measured timing was regenerated. Final mechanical validation: **20 tests passed**, plus syntax checks.

## Decision

The prototype provides evidence to pursue **wide, parallel, pre-LLM material supply** in the existing grounding path. It does not justify disabling supplementation or replacing the Keeper's judgment. The next design question is no longer merely whether Jev can find the relevant pages: it is how to present sufficient material so the writer uses it without redundant rereads and without turning limited evidence into overconfident prose.

No production cutover, App packaging/restart, world settlement, semantic-threshold tuning, or true-table acceptance was performed. Keep all controls, failed/partial possibilities, startup runs and raw artifacts. A broader corpus and genuine gameplay evaluation are separate work, not implied completion here.
