# 原始 PDF 的玩家视角题库

这是有原文锚点的**题库设计**，不是已运行的 Jev 基准、生产检索实现或真桌验收。两份原始 PDF 保持本地只读；仓库只存题目与必要的短引文，不收录 PDF 或全书文本。

## 文件与目标

- `QUESTIONS.md`：玩家问题目录，从结构化记录生成，适合先读。
- `cases.json`：设计情境、自然问法、分散证据、答案要求、玩家公开边界、增量变体建议及陷阱。
- `sources.json`：原件指纹、页数、页码约定、既有曝光及来源限制。
- `AUDIT.md`：实际核对结果、纠正过的问题、尚不能声称的结论。

要测的是：玩家提出一个实际问题时，材料供应层能否把分散在不同场景、章节、手卡或附录中的必要信息拼齐。命中一个名字、一页相关内容，不等于够用了。后续可比较既有逐页选择与考虑已有上下文、候选互补关系的联合选择；本次不实现或运行这种比较。

## 一题是什么

一题是一组合理的玩家处境与自然问题，不是声称录自真实玩家的话。重点是调查、判断证词、求援、营救、逃脱、使用已取得的物品和评估行动后果，不是让玩家扮演守秘人背目录或列参数。

翻译、重复运行、候选顺序、已供材料多少，都是同一题的变体，不计为新的独立题。问题可同时具有多个难点。

《血色公路》与旧实验是同一文件；新题不等于新书盲测。《Masks》也已在设计阶段被阅读。**本题库没有任何已取得的 held-out 成绩。** 以后调提示或策略前，应把共享解法／证据的关联题放进同一开发或保留分区，不能拿其中一题调参、把相邻题叫盲测。真正的新书泛化关卡需要另一份未参与调试的来源。

## 记录的含义

| 字段 | 含义 |
| --- | --- |
| `player_context` | 设计的当前处境及已取得信息；是组件题前提，不声称发生过真实行动或成功检定。 |
| `question` | 玩家自然问法；不带目标页码，不把隐藏答案当提示。 |
| `evidence` | 短原文、物理页、已核准的印刷页、小节、材料贡献、公开状态、native／visual 核验方式。 |
| `answer_requirements` | 守秘人处理问题所需的事实与限制；仅供评估，不是原样交给玩家的标准台词。 |
| `player_answer_boundary` | 该阶段可以透露或判断到什么程度；备料齐全不等于免费揭密或预告未来。 |
| `partial_context` | 建议的缺料干预：已有哪部分、还缺哪部分；目前是设计描述，不是已执行的 span 选择。 |
| `traps` | 容易混淆的相似材料、错误条件或推断。 |
| `unresolved` | 真正的缺文、矛盾、可选安排和版面限制；不能为了单一答案静默补齐。 |
| `evaluation_role` | 分散证据设计、材料已足够对照或未知结果对照；不是已经测出的难度标签。 |
| `partition_group` | 关联题的保守分组建议；尚未划定开发／保留分区。 |
| `optional_context` | 对照题中有帮助但不应强制取入的背景。相应证据可带 `necessity` 说明。 |

物理页从 1 开始；`printed_page` 是字符串或 null，不能与物理页暗换。短引文只锚定相关段落，不声称这句话独自包含整道题的全部答案。冻结可执行证据区间前，必须检查完整相关段落。

公开状态随情境而定：`keeper_only` 不表示守秘人不可检索，而表示不可自动向玩家披露；`acquired` 必须由情境中的实际发现支持。友好不等于全知，知情不等于愿意说，猜测不等于事实。

## 真正的分散证据

优先保留需要两个以上独立小节互补的问题，例如：

1. 物品取得地点，加上附录里的实际使用限制。
2. 前段线索，加上后段证词或档案，才能判断一种解释是否成立。
3. 拟走路线，加上沿途、返程或出口的另一处条件。
4. 局部破坏，加上下游替代方案、备件或仪式依赖。
5. 一种效果，加上会改变玩家计划的例外。

两页重复同一句不是多跳；硬塞一段遥远但无关的材料也不是。绪论的全知梗概不能替代玩家可取得的证据链。

**同章跨场景、正文跨附录、真正跨章节应分开报告。** 页码距离不是难度指标；`evidence` 中的背景材料，也不能自动升级成不可缺少的条件。

## 后续实验怎么用

对适用的基础题，另行构造不泄漏评估答案的输入：

- 完全未供相关材料。
- 已供部分证据，但缺某个明确条件、后果或例外。
- 必要材料已齐。
- 包含必要事实的忠实改写，对比丢失关键条件的主题摘要。
- 互补、可替代、重复以及可选背景同时成为候选。
- 适用时加入矛盾说法、无来源断言、错书或错规则模式。

Classic／Pulp 按题目条件固定，不能混用。两书中的沙漠、辐射、毒物、道具、怪物即使词汇相近也不能互套。跨书干扰是后续实验变体，不是把两部故事合成一个世界的许可。

正式运行前，把每条需求绑定到经验证的原文区间，并记录可替代的充分支持组合：必要事实之间是 AND，同一事实的有效证据组合之间可以是 OR；一个组合内部又可能需要多个片段。可选背景既不计为必需覆盖，也不自动判错。

**不得把 `answer_requirements`、目标页码、预期决策、`traps`、`unresolved` 或“这组缺什么”的标签塞给 Jev。** 供决策的输入只能是实际问题、当前上下文、带来源的候选材料及合适的来源元数据。本次尚未实现这条输入隔离或评分器。

## 应分开看的指标

- 必要事实、条件与例外是否齐全。
- 缺料时误报“已经足够”。
- 漏掉可取得的材料，与原文没有写、视觉材料尚不可读的区别。
- 精确来源重复，与语义重复的区别。
- 可选但有帮助的背景，与无谓补料的区别。
- 来源、规则版本、时间、观点归属是否正确。
- 守秘人内部备料，与玩家实际可见内容是否越界。
- 新增字数／token、轮次、延迟、预计费用。
- 后续带工具读者的正确性和补查量，不能拿材料命中率替代。

字少但答不出，不算节省；答对但整书都塞入，不算最小补料。revision 检查、同一原文区间的去重是宿主机械保证，不是 Jev 的语义功劳。原书没有穷举某个新方案，不等于玩家不能尝试；未知应交回守秘人判断，不伪造一条禁止规则。

## 来源限制

《Masks》有多栏、图像手卡、地图、Pulp 旁栏及局部覆盖规则。《血色公路》部分 native 文本损坏，且若干年份与细节不一致。有疑义就保留限定，不能强凑唯一答案。地图几何与图像独有信息需要视觉访问；native 缺字不是 PDF 没有该信息。

本题库面向守秘人与评估者，含剧透。营救与威胁题采用克制描述，不需要复述虐待细节。本次没有启动战役、结算状态、调用 Jev、安装或打包应用。
