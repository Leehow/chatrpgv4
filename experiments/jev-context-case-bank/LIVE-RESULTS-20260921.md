# Jev 八类对照实测：联合选料没有显示整体胜出

## 结论

这轮真实调用支持的结论很窄：**Jev 能在这个固定小候选池中找到足够的材料，但“最小增量”“当前语境绑定”和“来源类别”仍不可靠。机械枚举组合的联合选择没有显示整体优于逐候选判断。**

联合策略的补料文本少了一些，但精确选料正确数相同，完整判定少对一条，调用 token 略多，延迟没有一致改善。不能因此宣称端到端更快、更省，或据此替换生产策略。

## 实际执行与冻结

- 模型：所有正式响应均为 `jev-1.13.0`；真实 `POST /v1/systemone`。
- 4 次原始菜单小探针、1 次全部64组合协议探针、78 次正式请求、6 次事后诊断：**共89次API调用**。
- 正式部分：28个输入臂各跑两遍，共56次联合请求；其中11个选择臂另跑两遍独立候选判断，共22次。它们不是78道独立题。
- 78次均HTTP 200、协议有效，无不可用记录；并发4，正式调用阶段墙钟 **8.086秒**。
- 两遍按相反的执行次序调度，但相同题臂／策略的请求正文不变；39组重复请求的hash全部一致。
- 题库与gold冻结于 `7faac5157`，没有按结果修改问题、预期或阈值。请求与评估绑定分开保存，gold不进API。

正式策略与小探针不同：为了避免手写菜单提前裁掉困难组合，正式联合选择按候选池**机械枚举所有子集**，最多6个候选、64组合；不根据当前臂答案删选项。独立策略在同一state上逐候选判断 `adds_needed/redundant/unrelated/uncertain`，再汇总全部 `adds_needed`。

## 公平配对结果

全八类联合请求的原始结果为 **43/56 全部判定符合预期**，共同判定字段为89/98符合预期；原始失分（包括下文单列的题面歧义）全部保留。这是题库诊断总量，不用于与独立策略横比。

策略比较只取双方都执行的同一 `dataset/case/arm/repeat`，共22对，即11臂各两遍。不要拿联合的全部56条与独立的22条直接比较总正确率、成本或延迟。

| 配对指标 | 联合全部子集 Choice | 独立逐候选 Choice |
| --- | ---: | ---: |
| 请求有效 | 22/22 | 22/22 |
| 全部判定符合冻结预期 | 15/22 | 16/22 |
| 精确选料符合允许组合 | 18/22 | 18/22 |
| 声明所需证据单元被覆盖 | 22/22 | 22/22 |
| 原始选择的文本单元字节 | 5,812 | 7,282 |
| 宿主精确归一后的新增文本字节 | 4,240 | 4,784 |
| API报告输入token | 36,818 | 35,442 |
| API报告输出token | 5,924 | 4,924 |
| 单请求p50延迟 | 383 ms | 380 ms |
| 单请求p95延迟 | 463 ms | 482 ms |

联合新增文本少 **11.4%**，但输入token多 **3.9%**。字节优势全部来自甲虫同一题族的少量重复臂，主要是独立策略额外保留了改写重复和鼠群材料；不能推广为普遍节省。

“证据单元覆盖”是对固定允许组合的来源／文本单元包含检查，不是下游答案正确率。归一只消除精确相同来源单元或完全相同报告文本，不做语义去重，也没有实现任意重叠区间的扣除。

尤其是“已经齐料却仍选A+B”的联合输出，宿主可以把新增字节扣到零，但**原始选料仍然错误**，不能把宿主兜底改记成Jev选对。

## 八类中看到了什么

以下类别会共享题目，不把各行计数相加形成总体准确率。

| 类别 | 正式观察 |
| --- | --- |
| 同对象不同用途 | 甲虫分布／火焰效果分流、椅子观察／挥击符合预期。只证明这些具体对照。 |
| 多段材料合取 | 所选集合能覆盖必要片段；没有因此证明集合最小。 |
| 上下文保真度 | 正式两策略均能在这些臂中区分完整、半料、主题摘要及cache-only；但忠实报告被误判为已有完整原文支持，双方两遍都错。 |
| 联合去冗余 | 联合空上下文能选A+B，但已有A仍回选A+B，两遍相同；A+B已全有时，自己答complete却仍选择A+B，两遍相同。独立策略会把互补、重复、组合包同时选入，并偶尔取入鼠群材料。 |
| 记忆更正与当前状态 | 撤回前、撤回后、迟到旧抽取三臂均符合预期。它是契约派生组件题，不证明实局内核事务。 |
| 观点归因与证据方向 | 反向解释和来源归属臂符合预期；支持臂两遍判反向，但题面同时放了另一条Player负面解释，并在situation中提到“其观点”，存在输入目标绑定歧义，不能直接归因成不懂supports。 |
| 目的及公开／空间范围 | 宅外／入内与不自动发现日记符合预期。“那看看报纸”两遍被判选择报馆目的地，超出冻结授权预期；但batch仍为not_ready，没有整批放行。自然话存在省略空间，归因要克制。 |
| 未知与相关冲突 | 明确互斥与无依据新增效果分开判断，相关绳长矛盾可识别；问人数时，两遍仍把题外绳长矛盾判为conflict，同时又答requested fact settled。其冲突confidence为0，不能写成强确信误判。 |

完整原文支持还出现一次重复翻转：同一 `original-full` 请求第一遍答complete，第二遍答incomplete，第二遍概率仅0.51/0.49。全部39组相同请求里，有3组choice发生变化：此项，以及独立选料中两次鼠群候选分类变化。没有据此推断随机机制或执行顺序的因果效应。

## 明确错误与题面问题分开

- **明确增量错误：**正式019/060已有A仍取A+B；021/058已有A+B且自报complete却仍取A+B。
- **明确来源边界错误：**029/050及030/049把existing中的context_report判成完整原文支持；原文实际只在candidates。027/052的原文支持分类翻转也保留。
- **明确请求范围失分：**035/044问人数与指挥，绳长分歧不应让当前请求的consistency变成conflict；但这是近决策边界的错误离散选择，不是观察到了内部推理。
- **归因有限：**001/078目的地过度推断不等于整批越权；005/074的Globe方向题有“当前request还是另一条争议记录”的绑定歧义。原始分数不删，不把歧义重新判成通过。

## 事后诊断：只定位问题，不刷分

另存6次单次探针，不并入正式分数，也不称为修复后的盲测：

| 改动 | 实际返回 | 能说明的边界 |
| --- | --- | --- |
| faithful只去掉selection问题，候选原文仍在 | 内容complete、原文支持仍complete | 不是单纯多了selection问题才出现该失分 |
| 在上一步基础上去掉候选原文 | 原文支持改为incomplete；内容反而变missing，confidence 0.06 | 对候选可见性敏感，不能说已经修好了上下文判断 |
| Globe只留方向问题，仍有另一条Player负面记录 | reversed | 去掉归属问题没有消除歧义影响 |
| 再去掉该争议记录，保留当前request与图关系 | preserved，confidence 0.98 | 支持“比较对象绑定”是重要排查方向；不证明模型原来确实采用了某条推理 |
| 人数题的consistency增加uncertain选项 | clear | 选项集合会影响结果；一次返回不构成校准或修复证明 |
| 已齐甲虫材料时，宿主先删完全已供的原文候选，仍保留语义改写和鼠群 | selection空集，但content变missing | 精确预过滤有必要；仅靠该探针不能宣称整个门已正确 |

## 对主线优化的含义

1. **不要把“已有context判断”和“看候选选料”无差别塞进共享state。** 本轮混合批次出现材料可见范围混淆。下一次应优先沿用／验证既有分阶段路线：先只给当前上下文做gate，确有缺口再给候选。这里是下一轮实验方向，不是已经完成的生产修复。
2. **代码组合原子判断，不能假定同批Choice彼此一致。** content=complete却selection非空是真实反例。已有“足够则不进入补料”的控制流可以约束这种不一致；不能把约束后的成功回填成模型原判。
3. **来源身份与实际供给边界归宿主守。** existing内没有任何原文这一否定事实不需模型批准；但某段原文是否覆盖开放问题全部条件仍需语义判断，不能仅凭source_excerpt存在就判齐。
4. **先把当前目标、历史说法和来源声明分开投影。** Globe问题应在新版本明确绑定目标字段后复测，而不是改这轮gold洗分。
5. **尚不能声称整体更快、更省。** 没有运行下游带工具读者、无Jev基线或真实守秘人，因此没有端到端质量／补查量／总成本结论。本轮也没测Masks全书发现。
