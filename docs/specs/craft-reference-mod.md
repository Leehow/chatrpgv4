# 表达参考增强 Mod（Craft Reference）

日期：2026-09-24。状态：**已退役（2026-09-25）：选卡机制已删除、卡片归档，文风改由 [prose-mod.md](prose-mod.md) 的单一文笔 Mod 承担（契约 §30.7f）。**

本页以下保留首版实施时的设计记录。其中“默认 off”“基础提示/style 不改”已被用户后续裁定及契约 §30.7d 取代：基础指导一致化、同交换参考生命周期和 v2 默认开启已落地。最新验证见分票文档的默认开启补充记录；不以先前纯文本说话人评分冒充结构化界面的表现。

规格编写阶段仅产出文档；用户随后批准实施计划。当前源码基线为 `0.9.5a@ef8efdf97`；实施前重新确认最新开发线及实际源码。工作区已有的 v1 删除与 `docs/pi_coc_craft_v2/` 输入材料不是本规格任务的改动。

切片与依赖：[craft-reference-mod-tickets.md](craft-reference-mod-tickets.md)。本地工单与运行时批准计划是本次分票载体，不创建远程 issue，不沿用历史工单的已完成状态。

## Problem Statement

玩家需要的是更会回应、更有人物声音的守秘人，而不是更多文学审查。当前表达提示主要提供底线和抽象方向，缺少能按当场交流选择的具体技法与示范。与此同时，新的指导不能夺走守秘人的兼容即兴权，不能改变规则、玩家选择或模组真相，也不能把等待、误报与强制改写变成新的游玩负担。

用户选择以**可选增强 Mod**融入 craft v2。因此本规格不执行 v2 的全局两文件提示补丁，不把全桌基础风格改写捆绑进来。成功是：启用该增强后，原来的 Keeper 在真正的请求中获得少量相关指导，能自然回应；关闭、无合适卡片、超时或预算不足时，原路径仍完整可玩。文件齐全、卡片数够、单测通过或 selected 日志出现，而实际请求未收到内容、文章没有改善，都是空心交付。

## Solution

沿用现有 **Narration Craft / 叙述手艺** Mod 的身份，发布显式升级的新版本，而不是再建一个职责重叠的写作 Mod。

分两项交付：

1. **Mod 内的正向指导**：在新版本的 full/brief 提示中吸收 v2 的交流目的、人物动机、自然句法与兼容即兴原则；不改全局 Keeper 提示或基础 style 图。
2. **可选的动态表达参考**：新增 `reference_mode: off | jev`，默认 `off`。开启后，由宿主使用既有 Jev 类型化决策，从最多 12 张候选中选一张或 `NONE`，注入一个有严格预算的英文参考块。原 Keeper 仍负责判断、工具使用和成文。

这里的“参考”不是动作授权、事实来源或待完成任务。Mod 不是执行 JS 的插件；它贡献英文 Markdown/JSON、版本与设置。代码、生命周期、模型调用与请求投影由宿主拥有。不新增 Keeper 工具、skill 义务、第二个写作 Agent、同步文学评分或发布门禁。

## User Stories

1. 作为玩家，我希望直接问题得到直接回答，而不是每次都先读一段气氛描写。
2. 作为主动观察的玩家，我希望现场允许适度铺展，而不是被统一短句规则压扁。
3. 作为与 NPC 交谈的玩家，我希望相同的拒绝能体现人物已有的顾虑和关系，而不是职业模板或神秘警告。
4. 作为选择安静、玩笑、陪伴或拒绝的玩家，我希望这些都能成为完整的一回合，不被强塞新事件。
5. 作为调查员的控制者，我希望我的感受、信任、意图与未选行动仍由我决定。
6. 作为探索模组的玩家，我希望比喻、范例和人物语气不泄露秘密或伪造线索。
7. 作为参与规则结算的玩家，我希望参考不会改变结果、资源、时间、位置或物品归属，机制仍由专用 JSON/UI 交付。
8. 作为战役拥有者，我希望在现有 Mods 面板升级、启停和配置，不另学一个工具或设置入口。
9. 作为已有存档的拥有者，我希望旧版本锁、已交付文本和收据不被自动迁移或改写。
10. 作为刚启用新版本的玩家，我希望额外 Jev 调用默认关闭，显式开启后才发生。
11. 作为关闭该 Mod 的玩家，我希望没有卡片读取、选卡请求或表达参考注入，原游戏继续工作。
12. 作为开启参考的玩家，我希望没有合适方法时自然跳过，不强行使用卡片或轮换技法。
13. 作为取消输入、恢复会话或切换世界线的玩家，我希望迟到的参考不能污染新请求。
14. 作为非英语玩家，我希望守秘人直接使用开放的 `play_language`，而不是机械翻译英文例句。
15. 作为开发者，我希望能区分候选找到、选中、最终注入、输出被检查，而不是把 ID 或哈希当成文笔提高。
16. 作为维护者，我希望宿主只暴露一个窄的声明式表达参考能力，不引入通用任意代码钩子。
17. 作为体验评估者，我希望允许平手、无改善或更差的结论，并分别看到内容质量和新增等待。
18. 作为使用现有密度设置的玩家，我希望该设置保留为原来的可选指导，本次不会默默删除或强化它。

## Implementation Decisions

### D1. 包身份、版本与开关

- 保留 `narration-craft` 身份。当前基线为 1.3.1；首个候选版本建议 1.4.0，若实施时已有更新则按当时版本递增，不覆盖任何已冻结版本的字节。
- 保留现有包默认启用语义、`density_guide` 设置与 state version；**新增动态参考默认关闭**，不因凭据存在、包升级或继承环境变量自动开启。
- `reference_mode` 只接受闭集 `off | jev`。`off` 表示不做动态卡片读取/选择/注入；已显式升级的新版本仍提供自己的普通 full/brief 指导。**整个 Mod 关闭**才表示该包所有指导均不出现。这两个对照不得混淆。
- 新战役遵从现有默认配置；旧战役只经已有显式版本升级与安全边界激活。忙桌变更继续进入 pending，不绕过现有配置协议。
- 不新增顶层 UI 页面；现有 Mod 设置 schema、版本选择与开关承载功能。新生成的产品文字只有英文源，经现有展示路径处理，不新增按语言手写的字符串表。
- 新参考模式需要有效的既有 Jev 挂载、模型配置和凭据。缺失时保留设置但报告功能不可用、跳过参考；不读取全局凭据、不假装成功，不把不可用编造成剧情。

### D2. 内容的单一归属

- 新版 Mod 的 full/brief 提示负责正向手艺；基础 Keeper 提示和 style 图保持不变。本规格不解决所有旧文风问题。
- 从 v2 的 48 张卡保留英文规范资产及 12 张 starter 候选。中文审阅、文学摘录、浏览器、研究报告、安装脚本和测试夹具不是生产 Mod 资产。
- Mod 只携带声明的 JSON/Markdown。TypeScript helper 归宿主运行时，不打入 Mod 成为可执行负载；不为本地 helper 引入新的发布包或独立 HTTP 客户端。
- 运行时正常生成只展开正向目的、适用/不适用条件和至多一个短正例；不注入反例、诊断、整套教材或作者模仿指令。
- `acceptable / stronger / alternative` 是编辑标签，不是质量真值。初版沿用 v2 的 `stronger` 作为有标记的“一种可能写法”，无需另一次模型调用选例；离线对照检查这个默认是否造成过度修辞。
- 48 卡是可维护资产，不是每轮指令数；初版候选固定为经过审阅的 12 张 starter。没有关键词场景路由、随机轮换、冷却义务或隐藏向量服务。扩大候选池另行以证据决定。
- 两个已有约束暂不扩展：开场配额和重复台词规则不由范例覆盖。需要原句重复或额外开场铺展的教学例不证明生产会接受；若实测冲突，保留失败证据并单独报告，不能偷偷修改拒绝语义。

### D3. 新增窄的声明式能力，不新增任意 Mod hook

以下是本次新增的契约形状，已先写入内核 RPC 契约 §30.7b/c，再由 CR-02/03 实现。代码验证、离线诊断与真实服务验收的状态分开记录，见分票实施记录。

- 新能力 `context.craft-reference.v1`，新贡献 `contributes.craft_reference` 指向一个包内 JSON 描述文件。
- 描述文件使用 schema version 1，引用包内英文 catalog 与 starter ID 清单。引用必须是规范相对路径、存在、列入 `package_files`、属于当前冻结包，不能越界、指向审阅材料或运行代码。
- 新增宿主只读方法 `mods.craft.read`，不进入七个 Keeper 动词。参数包含当前战役、`mode: index | card`；card 模式另带一个宿主已发出的 card ID 及预期包/资产摘要。不开通客户端任意文件路径。
- index 返回当前有效贡献的包 ID、版本、digest、设置、catalog revision，以及最多 12 个候选的 ID、目的、适用条件、例外；不返回整套正反例。card 只返回所选卡的生成白名单字段。
- 返回值包含由既有权威读取的战役/世界线/Mod 锁绑定。禁用、无有效贡献或 mode off 时返回明确的空结果，不读取 catalog 正文、不触发 provider。只读方法本身不注册新世界事实。
- 复用已有加载顺序规则，在 `craft_reference` 单一贡献槽中后置有效提供者覆盖前置提供者；不拼接多个包的卡片。已有纯 instructions 的叠加语义不改。返回选定提供者身份，结果采用时重核该身份。
- 老宿主不认识 capability 时按现有机制显示不兼容，不把新包当作损坏目录导致整个目录失败；旧锁仍能使用旧包。
- 不把 `create / usage / audit` 三类 Mod 写任务扩大成文笔任务；参考选择不进入审计账本，不生成结算收据。

### D4. 三端职责与唯一请求接缝

| 对象 | 谁写 | 谁读 | 谁据此行动 |
|---|---|---|---|
| 表达卡与正向原则 | 版本化 Mod 内容作者 | 宿主资产读取与渲染器 | Keeper 自主借鉴，不产生执行义务 |
| 候选与当前语境 | 现有场景、人物、输入和历史投影拥有者 | 宿主的类型化选择适配器 | Jev 只返回已发行卡 ID 或 NONE |
| 选中参考 | 宿主校验结果并展开真实资产 | Keeper 的真实出站请求 | 原 Keeper 决定如何说，仍使用原工具和收据 |
| 采用证据 | 宿主请求观察器与已有回合证据 | 开发者、离线评估与真人 | 决定是否保留增强，不反馈成下一轮义务 |

最高测试接缝是：**配置与真实输入 → 实际宿主上下文投影 → provider-bound Keeper 请求**。卡库 helper 的测试不能替代这个接缝。

- 宿主在现有上下文准备/请求投影链中组织参考，不把它塞进 procedure skill、基础 style 列表或整包 instructions。
- 使用独立、仅宿主可发行的 `coc-craft-reference` 传输消息。内容以英文标明 optional、separate example、not campaign evidence；不能由玩家引文或历史伪造同名块获得发行资格。
- 卡 ID、包摘要、选择绑定等仅放宿主 metadata；正文无卡号、调试说明、审计结论或新增玩家选项。参考不含当前秘密原文或新的剧情断言。
- 不在持久聊天历史中保存活跃参考消息，不作为 memory/world 状态；需要保留的证据进入现有内部遥测/玩测目录。重新加载历史中的同名消息不算当前发行。
- 正文仍由同一个带原工具的 Keeper 写；说话标记、mechanics JSON、玩家控制权、秘密披露和现有审计不变。

### D5. 选择生命周期、时效与调用成本

- 注册宿主 Jev family `craft-reference`，通过既有 `DecisionPort`、配置、provider adapter 与 `TaskLease`。不使用裸 provider completion，不另设 key 流程。
- 状态只取已在当前宿主上下文中可用的玩家输入、当前场景、相关 NPC 既有动机/关系/知识和必要近期交流；信息缺失可返回 NONE，不启动源文补读、NPC 生成或第二次分类。
- 每个已接受玩家输入 epoch（含自动开场的独立 epoch）至多启动一次选卡请求。普通工具续行、压缩重建、重试 provider 或重新投影不再次付费选卡。
- 首版不使用跨轮 `KEEP_CURRENT`。在同一有效输入 epoch 内可复用结果；跨轮选卡与缓存实验留后，避免先引入维护收益尚未验证的风格状态。
- 初始选卡等待上限为 **1500 ms**，并受父任务剩余 deadline、tokens、cost、actions 的更小额度约束。这是待测的工程上限，不是测得的 Jev 延迟或质量阈值。provider usage 由既有 adapter 只记一次，超时仍记录实际发生的消耗。
- 输入、战役、世界线/loop、源和图版本、相关世界/NPC/记忆读取版本、有效 Mod 版本/digest/settings、catalog revision、model/family revision 共同绑定；只比较 turn 编号不够。
- 选择返回后、读卡后和首次实际注入前，均核对现有 read set、当前有效提供者及 AbortSignal/generation。取消、重置、切线、新输入或相关修订使未发行结果失效。
- 同一轮一旦发行，后续 inference 不能再次追加重复参考。若依据失效，不能继续把旧参考标为当前有效；服从当前引擎的请求政策。单循环路径保留已发前缀，只通过其已有追加更新机制声明失效，不重写已发前缀；模型已经看过的内容不能宣称被撤销。新输入只携带当前有效参考。
- 当前单循环路径与既有兼容路径共享同一参考准备器和发行校验，不同时启动两个 selector；主路径由 run owner 调度，兼容路径接入现有 context 生命周期。不得以本功能重写 Pi 引擎或添加外层 ReAct 循环。
- `NONE`、非法/未发行 ID、缺答案、超时、异常、provider 不可用、资产损坏、过期、预算不足均跳过参考。不重试、不叫另一个 LLM救场、不拒绝已接受玩家输入、不取消原回合。安全/授权车道的拒绝策略不受此处可选失败回退影响。

### D6. 两层预算与请求缓存

- 参考渲染默认上限 **1800 UTF-8 字节**，宿主再次硬夹紧；不新增玩家可见的字数、段数、感官数量目标。
- 若正例放不下，整块移除正例；方法也放不下，整个参考不注入。禁止截断半句、半个样例或为了卡片裁掉事实。
- 在已经合法打包的**无参考请求**基础上使用剩余空间。当前输入、系统/工具、结果配对、当前胶囊和原本保留的必要证据不得因表达参考而丢失。没有余量就跳过，而不是扩大整个请求上限。
- v2 全局提示替换造成的 style 超预算问题通过“不执行该替换、参考走独立可选余量”规避，不在此扩大 style 预算或修改基础图。
- Mod 锁/settings/provider 变更参与 briefing cache key 和失效事件；不能只依靠 source revision。关闭或升级生效后的下一次合法请求必须反映新有效集，不能残留旧包指导。
- 请求前确认使用现有 provider-bound 观察接缝，不修改 payload 以伪造确认。不记录密钥、请求头或默认整份私有上下文。

### D7. 状态、遥测与观察权限

- 复用现有 Mod 面板显示版本、启用与 `reference_mode`；宿主诊断区分 configured、available、active，不在玩家叙事里反复报告服务状态。
- 至少分别记录 candidate set、selected/NONE、rendered、injected、omitted，以及明确原因；记录 run/input/request correlation、包与卡摘要、字节、耗时、调用次数和已有 usage 引用。
- injected 只能由最终实际请求确认；prepared/selected 不能冒充 injected。output-reviewed 由具体输出检查/盲评证据给出，不能用匹配哈希或字符串命中代替“采用”。
- 不保存新的 NPC 声线状态、不写世界状态、不产生文学债务、不以未使用参考催促后续回合。遥测只服务诊断。

## Testing Decisions

### T1. 确定性与实际请求接缝

- 先写新能力和只读读取形状的契约，再写实现。选择 helper 的协议测试保留，但以真实宿主准备、投影与 provider-bound 消息为主断言。
- 保留原包、旧存档锁与原资产；用隔离新战役或测试副本检查升级、pending 生效、禁用、重启、世界线隔离和包加载顺序。不在用户战役上试开关。
- 测试 full/brief：提示使用新包版本且不重复，基础 style 在参考开关前后逐字不变；模式 off 不发起选卡，不读卡正文，不发行参考。
- 包安装/导出仅包含声明的英文 JSON/Markdown；runtime 构建收集 helper；review、research、HTML、TS 和 provider key 不进入 Mod 包。旧宿主遇到未知 capability 明确不兼容。
- 测试 valid / NONE / wrong batch / foreign ID / missing answer / thrown error / deadline / cancelled / stale read set / changed provider / corrupt catalog / insufficient budget；全部不引入新的回合失败。
- 验证重复 prepare、工具续行、provider retry 只消耗至多一次选卡预算；跨战役/世界线不能复用结果；已发送参考失效遵守单循环追加更新而非改写缓存前缀。
- 删除实际注入调用，测试必须失败；只写 selected 日志也必须失败。请求末端裁掉参考时必须记录 omitted，不能仍记 injected。
- 用假时钟和受控 DecisionPort 做失败/取消测试。它们是软件契约测试，不是 Jev 能力测评或真桌记录。
- 原有机制、说话标记、授权、审计和开放语言守卫继续运行；不修改系统语言守卫去迁就新包。

### T2. 文笔与选卡的独立收益

四个条件使用同一实际模型配置、同源上下文和已结算结果：

- A：当前 Narration Craft 版本，动态参考不存在。
- B：新版 Mod 正向指导，`reference_mode=off`。
- C：B 加人工选定参考，仅用于受控离线比较。
- D：B 加真实 Jev 选择，候选库与 C 相同。

C 的固定选择只通过测试/离线依赖注入，不发布为生产关键词路由或新手工工具。离线生成使用带工具 Pi agent，不使用裸 completion、不冒充真实游玩。事实锁定改写与允许兼容即兴的 Keeper 成文分组记录。

样本来自保留的真实回合，提供必要原输入、人物状态、公开/私有边界与结果；按战役/场景分离调试与保留集，不以教学卡或它的改写自证泛化。覆盖直接确认、NPC拒绝/温暖/幽默、安静休息、长观察、失败检定、重访、开场、跨轮和非英文表达。

盲读允许 A/B任一、平手、都不好；分开记录承接、自然度、人物声音、场景适配、连续性、玩家自主性和整体偏好，不合并成可抵消泄密的总分。不规定先验“胜率达标”数字，也不把篇幅增长当改善。

可先由独立、看不到条件标签的带工具评估者提供诊断；这不是人类偏好证据。有合格真人反馈时另记来源与分歧；未取得就明确人类/多语言校准未完成，不阻塞代码归档，也不宣称玩家体验已证实改善。

### T3. 正式真桌与性能

使用当前项目唯一真桌方法：`tests/play/driver.py` RPC 启动 `bin/pi-coc`，建卡用 `bin/pi-coc-setup`，默认 `grok-build/grok-4.7-build-fast` / low 当 Keeper，**主会话是唯一玩家**，一句自然话一回合，从开场玩到结局或真实阻断。不得委派一个 scripted player、替代 Keeper、批量结算或合成回合。

沿自然过程观察回答、NPC、安静场景、失败结果等能力，不为配额强造情节。保留原始回合、收据、遥测和输入；遇到问题不删证据。测试 fixture 只验证 plumbing，不是这项验收。

记录首次真正剧情内容、最终交付、可再次输入、实际选卡次数、token/费用、超时与fallback。相同模型、缓存、源准备和审计条件下比较；不把一个场景的速度外推为普遍收益。

通过源码模式验证现有 Mods UI 的开关/升级/刷新。界面可通过内置浏览器访问时不用桌面控制。**本规格不授权 App 打包、安装、推送或重启**。

### T4. 发布判定

分别列出：代码/协议、实际请求注入、真实 Jev 选择、离线表达效果、真人意见、真桌体验、延迟与多语言。某项未跑就未跑。只有可靠注入而无效果证据时称“功能已接线、效果待验证”。负收益或高跳过率是保留默认 off 的理由，不靠改教学金标刷绿。
