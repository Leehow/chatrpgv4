# 统一表达增强：整合 NPC 口吻与表达方法卡

日期：2026-09-24；实施核对：2026-09-25。状态：**统一入口与窄接管已实现，本切片隔离回归通过；真桌仍暴露行动准入/准备链缺口，不宣称整体体验无故障。测试执行由 Grok 4.7 fast worker 完成。**

这是 `craft-reference-mod.md` 的后继规格。基线为提交 `27cdf9974` 的 Narration Craft 1.6.0/default jev，实施版本为统一包1.7.1与旧口吻兼容包1.3.0（1.7.0已由首轮真桌冻结，未覆盖其字节）；实施与未通过的体验项分开记录，不重写此前实验或旧战役。用户本轮要求测试执行交给 `grok-build/grok-4.7-build-fast` worker，昂贵主会话负责实现、取舍与证据审阅，不再亲自跑长测试。

## Problem Statement

NPC Voice 与 Narration Craft 都在指导原 Keeper 怎么说话，存在重复常驻提示和两个用户入口。NPC Voice 又混合了两种职责：维护每个人的声音资料，以及提供通用的自然对话技巧。把这些全塞进“一轮最多选一张”的表达方法池，会让人物依据随抽卡消失；只是把两个包提示拼起来，也没有消除重复。

成功是：新战役只有一个主要表达增强入口；人物在场时，其已建立的身份、动机、关系、原书台词和可用口吻资料持续可读；NPC 通用表达优化进入统一方法卡；原 Keeper 一次成文，不增加同步写手或文学裁判；旧锁、旧生成卡和用户偏好不丢。

空心交付包括：列表少一项却仍重复注入两套提示；只改包名却重生所有人物卡；这一轮选了动作卡就没了 NPC 声音；把关闭旧包后读不到的旧卡当成无卡；用未保留对白结构的评分宣称改善。

## Solution

沿用 `narration-craft` 身份，发布下一个未占用的不可变版本，目标为 1.7 系列。用户入口统一，内部保持两个不同用途的上下文区域：

1. **人物依据区**：在场 NPC 的原有档案、原书声音/台词、明确建立并保留的声线资料。人物资料不是可选技巧，不占方法卡槽。它不创造新人格、秘密或说话权。
2. **表达方法区**：口语承接、人物间的语域区别、拒绝/合作、观察、动作、节奏等方法。沿用一轮至多一次 Jev、至多一张卡或 NONE 的路径。

新战役的候选默认路径：统一包开启，不再默认启动逐人 `mask + 三条交流例句` 的后台补写。它利用原书和已有 NPC 档案，让原 Keeper 成文。旧的后台声线生成代码保留为旧锁兼容路径，不新建第二条生成车道。

这个精简必须做同材料对照：如果出现明确的人物可辨性或持续口吻退化，先修人物资料投影、常驻短指导和方法卡；不得为了让计数好看而删旧样稿、机械重生直到赢，也不得悄悄恢复一条新的默认收费链。

## User Stories

1. 玩家只需启用一个表达增强 Mod，不需要理解两个重叠开关。
2. 场上有多个人时，每个人的已有声音依据都能到达 Keeper，不因选卡竞争而遗漏。
3. 原书给出的台词、人物知识、秘密和不说话的设定优先于生成资料与技巧示例。
4. NPC 能自然接话、合作或拒绝，不需要每句重复口头禅、职业梗、动作或神秘警告。
5. 表达卡可以 NONE；缺卡不代表 NPC 不会说话，也不阻塞当前回合。
6. 玩家仍看到原来的结构化对白、颜色和说话人，不更换对白协议。
7. 用户已有的粗话偏好保留，允许粗话不等于强制粗话；关闭只改变用词，不改变人物合作意愿或事实。
8. 旧战役不自动迁移。明确升级到统一版本时，可以接管已有 v2 声线而不丢卡、不重生、不启用归档的 v1 样本。
9. 忙桌的升级在安全边界整体生效，不能出现一轮两个 owner 或一轮没有声音依据的中间态。
10. 用户能看见真正少了什么调用、多少常驻上下文，而不是被告知“每轮省两次模型”这种不符合现状的数字。

## Implementation Decisions

### D1. 一个产品入口，不是把人物信息改成抽卡

- 保留 `narration-craft` ID、现有默认 `reference_mode=jev`、`density_guide` 与已有稀疏参考机制。
- 统一包贡献原书 `voice_mask` / `exchanges` 的既有 actor-profile vocabulary，让原书台词仍进入 `voices`。人物身份、动机、关系、知识继续由现有 NPC view 拥有。
- `voices` 与 `craft_reference` 分节，预算也分开。当前在场人物的声音依据不被单张方法卡/NONE覆盖；延用声音区先裁示例再裁人物的规则，不搬进1800字节方法槽。
- `say`、`marked_text`、`speech`、角色归属、对白颜色和 mechanics JSON 均不改。原书文字或玩家已建立的称呼不能为风格而改名。

### D2. 通用口吻优化进入现有卡库

- 先审现有 `CRAFT-VOI-*` / `CRAFT-DIA-*`，修改/复用已有方法，不复制另一套相同卡，不因合并就扩大12候选或每轮卡数。实际覆盖核对后，1.7.1将VOI-05改为“同一已定答案，不同既有语域”并纳入候选，SEN-04退回仍保留的48张库；候选仍12，调用上限不变。
- 自然应答、同一意思的不同语域、可完整结束的短答、避免职业口号等技巧可以入卡。
- 原书优先、秘密边界、听者身份、粗话偏好、例句不是台词库等不随选卡命中才生效的约束，留在一份精简的 full/brief 指导中。
- 合并后不同时注入旧 NPC Voice 的全局指导与统一包的同义指导。人物资料与通用技巧是不同信息，不以去重之名删除前者。
- 所有新增系统文字仍为英文；玩家语言开放，不加按语言/职业/名字硬编码的分类。

### D3. 新战役不默认补写每人的三句例子

- 新统一路径使用原书声音、已有 NPC 档案，以及明确保留下来的声线资料。它不因为缺 `exchanges` 而阻塞、自动启动第二作者或强制造口头禅。
- 旧 `npc-voice` 车道仍能服务旧启用锁；保持 source-authored 优先、`does_not_speak`、现有复核和发布新鲜度检查，不重写这条兼容车道。
- 不把已有后台写作误说成每轮调用：它目前是缺卡时的一次写作及复核，普通已有卡不会每轮重写。省下的是新人物补卡的后台工作与重复上下文，不预先承诺全回合提速。
- 不新增“生成策略矩阵”供用户配置。对照若证明需要改变上述默认路径，作为明确设计调整报告，不藏在实现里。

### D4. 旧战役明确升级时接管，不能默默迁移

基线 `mods.configure` 只支持同一 Mod ID 的迁移；本次增加的跨 ID 接管是两个内置包的窄宿主能力，不是任意 Mod 迁移框架。

- 旧锁继续使用原包、原状态与原生成链；安装新版本或打开旧战役不会自动转换。
- 只有用户明确升级/启用统一版本且目标为 enabled，才执行一次针对这两个内置包的接管；仅更新一个仍关闭的统一包锁，不停用旧声音 owner。接管与版本、设置、旧包停用在同一安全边界事务中生效。
- 接管当前有效的 v2 `dossier`，保留来源/版本信息；不删除原 `npc-voice` 命名空间，不重新采用 `legacy_voice_dossier` 中已归档的 v1 数据。目标已有条目不能覆盖；以每个NPC的一整张声音资料为单位，保留已有目标卡，不把不同来源的mask与exchanges拼成混合卡。冲突的旧卡保留在原命名空间并在接管结果中明确报告，事务不得半完成。
- 旧 NPC Voice 原来启用时，已建立声线转入统一包；旧包原来显式关闭时，不把其缓存当作已授权活跃资料复活。已有 `coarse_language` 偏好仍保留，调用中明确给出的新设置优先。
- 接管可重复调用但结果幂等，不增加重复卡、不重生人物。旧在途 job 不能在接管后回写旧活跃 owner 或覆盖新状态，过期结果保留诊断而不采用。
- 统一版本与独立 NPC Voice 不允许同时作为有效声音增强 owner；兼容配置检查和升级事务必须避免两个全局提示同时出现。
- 对新角色/新会话，只读取正确人物的资料；切换世界线、人物不在场和语义任务视图均维持现有边界。导入的编辑声线不成为规则事实。

### D5. 新入口与旧入口的可见性

- 新战役默认只启用/展示统一表达入口，不能因同一 home 中缓存了旧默认开启包而重新启用独立 NPC Voice。
- 独立包保留为兼容版本，发布新版本表达其非默认/兼容身份，不改已冻结的1.2.0字节。
- 旧战役尚有旧锁、启用状态或保留资料时，可以显示清楚标识的兼容项及升级去向；接管后不再呈现两个重叠的日常开关。用户的自装非兼容包不因名字相近被隐藏。
- 展示层需要的信息由宿主 Mod view 明确给出，不让 UI 猜状态目录；源文字只有英文，经既有展示路径处理。
- 接管支持须声明新的版本化宿主 capability；旧宿主应判不兼容，不能只加载一半提示却误以为完成迁移。采用内置包的专用适配，不搭建任意跨 Mod 状态迁移框架。

### D6. 三端与权限

| 对象 | 谁写 | 谁读 | 谁据此行动 |
|---|---|---|---|
| 原 NPC 档案和原书声音 | 既有模组读者/事实拥有者 | NPC view、voices | 原 Keeper 决定人物表现，仍受知识/结算约束 |
| 旧生成 v2 声线 | 旧兼容车道；明确升级由宿主复制接管 | 启用的当前声音 owner | 原 Keeper 参考，不当事实或固定脚本 |
| 通用口吻方法卡 | 版本化表达包作者 | 既有有界选择/投影 | 原 Keeper 自主采用，不生成执行义务 |
| 接管状态/偏好 | 明确的 Mod 配置事务 | Mod view、任务视图、voices、旧 job 的发布检查 | 宿主切换 owner，不触发叙事或隐式费用 |
| 成本/质量证据 | 真实请求、调用记录、独立测试会话 | 开发者与用户 | 决定保留/修正，不反馈成下一回合的文学债务 |

## Testing Decisions

- **执行模型与成本**：测试脚本、离线作者/读者、回归与测试会话由 Grok 4.7 fast worker 执行；主会话不重复跑长测试，负责审阅证据和必须由主会话工具完成的少量界面观察。
- **原方法边界保留**：真桌仍是canonical driver +真实生产Keeper、一次自然输入一回合，不用模板玩家、关键词脚本、批量结算或假Keeper。用户本轮明确把测试会话交给worker；该执行归属与此前主会话玩家基线单独标注，不混用结果。
- **最高接缝**：真实 Mod 配置/升级 → kernel voices 与宿主实际请求 → 原 Keeper 交付及结构化speech；字段存在或卡ID被选中不算采用成功。
- **新局检查**：只一个主要入口；在场多人都有原有依据；选择普通叙事卡/NONE时声音依据仍在；无新后台voice生成，缺卡不等待。
- **旧局检查**：旧开/关、v1归档/v2有效卡、已有目标资料、重复升级、忙桌pending、在途旧job、失败回滚；原状态和已交付记录不被删除，粗话偏好不反转。
- **成文对照**：相同来源与NPC、跨几个不同交流场合，比较现有独立口吻路径与统一路径；看自然承接、人物可辨/持续性、事实与自主性，不奖励口头禅或单纯更短。保留speech分段和说话人，不能只stripMarkers评归属。
- **成本检查**：逐NPC初次补卡/复核、每轮Jev选择、额外Keeper写作、上下文字节、交付等待分开记录。不能用不同场景时长相减声称节省。
- **边界**：测试不改用户战役；原回合、失败、样稿、旧卡和模型元数据保留。没有真人反馈就仍写human-calibration=not-run。

## Slices

1. **统一新战役路径**：包/口吻方法/常驻资料投影/新入口/定向接缝一并落地。新局能在一个入口下正常对话，原书声音与NPC档案不依赖选卡；默认不补新生成卡。
2. **旧锁安全接管**（依赖1）：明确升级的原子接管、旧偏好和有效v2资料保留、旧job拒绝过期发布、兼容入口展示与回归。旧桌不自动变化，明确升级才切换。
3. **Grok 配对优化与成本验证**（与1并行启动，使用冻结候选和资料；最终验证依赖1/2）：先按上述固定候选对照，不寻优刷胜率；有具体现象则修相应系统路径，不手写剧情补样本。
4. **集成与发布验收**（依赖1/2/3）：Grok执行回归与真实游玩、主会话核对必要显示证据，最后冷审和精确路径提交。分别报告功能、效果、费用/时间与未覆盖项。

## Out of Scope

- 删除旧声线/战役/试验，自动升级用户正在玩的战役。
- 任意跨Mod迁移框架、第二套人物事实/记忆系统、通用provider大重构。
- 新增同步文学评分/改写/拒绝车道、强制口头禅、增字数配额。
- 改规则、行动准入、秘密披露、对白JSON格式或NPC的源事实。
- Python内核恢复、冻结oracle修改、手写语言表。
- 未经请求打包/安装App、推送、重启用户宿主。

## 实施结果与验收边界（2026-09-25）

- **实现**：1.7.1 统一入口、常驻人物依据、显式 v2 接管、偏好保留、安全边界、旧 job 拒绝迟写与兼容行显示已落地。VOI-05 进入12候选，SEN-04仍在48卡库；单次选择与既有预算未扩大。新统一路径不启动逐人声线作者/复核，旧启用锁仍支持原车道。
- **回归**：Grok 在 `27cdf9974` 加26个本切片路径的隔离快照内重新构建，`check:kernel`、`build:runtime`、扩展2914项、相关内核82项均通过；测试结束时26路径与主树哈希一致。测试命令本身共约314秒，worker全程6分10秒。证据：`.pi/progress/unified-isolated/result.json`、`manifest.json`、`progress.log`。共享脏树此前的超时/失败保留在 `.pi/progress/unified-integration/`，隔离通过不代表并行物品改动也通过。
- **审阅与显示**：实现冷审及1.7.1增量审阅通过。真实 `mods.list` 驱动生产面板的三场夹具通过DOM检查；主会话核对桌面截图：新局单入口、旧锁兼容去向、升级后仅版本/计数诊断。没有进行移动端或安装包验收。证据：`.coc/evaluations/unified-mods-preview-20260925/`。
- **成文对照**：旧卡保留的小型合并指导对照和当前v2卡补证没有给出可推广的普遍胜负。旧批部分依据包缺项，v2补证的两场倾向不同，且观察到例句条件挟带。不能据此宣布生成卡无用或统一路径必然提升文笔；保留已有有效卡、不刷新样本追求胜率。`human-calibration=not-run`。
- **真桌事实**：同一隔离战役经正式 `mods.configure` 升到1.7.1，turn12取得 `campaign-end` / `outcome=completed`，是退还委托而非宣称宅子真相已查清。未出现声线作者或复核模型调用；结束后的一次 `voice.job` 返回 `campaign_not_ready`，不能把它写成“零RPC”。证据：`.coc/playtests/unified-expression-cont-20260925/REPORT.md`、逐回合记录及原战役存储。
- **未解决的整体体验缺口**：turn7/10/11没有提交正文，标记为 `stranded`。最早的移动被准入以目的地未授权拒绝，其后出现beat/scene锚点歧义、未注册中文目的地、准备任务pending；另有 `Adaptation create task failed (143)`，退出来源未查明。Keeper未调用 `narrate`，位置没有随口头叙述移动。已有证据不指向声线作者或本次选卡，但没有做因果对照来证明提示绝对无关。结局收据不抹去这三次失败，**整体无故障游玩验收未通过**。行动准入/准备链在本规格范围外，保留证据并单列，不扩成另一轮修复。诊断锚点见 `.pi/findings/unified-live-gap.md`。
- **费用与范围**：没有新增同步写手、文学裁判或逐人补卡调用；未以不同场景耗时相减宣称全回合提速。未打包、安装、推送或重启App；并行物品文件、原输入包与全部旧证据保持原样。
