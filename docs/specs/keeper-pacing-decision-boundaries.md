# 守秘人节奏：推进已选行动，在真实决定前交回

日期：2026-09-19。状态：规格，未实施、未真桌验收。基于当前开发线 `0.9.3a`、勘察基点 `80111ecd9` 与工作树现状；运行时实现只在 TypeScript 生产路径维护。

## Problem Statement — 问题陈述

玩家感觉剧情推进像“挤牙膏”：已经说明要做什么，守秘人仍在普通中间步骤结束时停下，让玩家再说一次。另一端同样错误：玩家只说拿上钥匙，守秘人却替他决定前往科比特老宅。加快节奏不能以失去角色控制权为代价。

用户要的是：**已选的事不拆碎反复问，未选的事不擅自做；交回点是能改变后续局面的未选决定，而非动作、句子或工具调用的边界。** 玩家完成当前目标、尚未选择下一目标，也是合理交回点。

当前实现不是缺一个“加快节奏”口号，而是既有路径不一致：

1. `keeper-pacing` 1.2.3 默认启用，已有公平警告、威胁钟和停滞恢复指导，但没有把正常回合的行动范围与交回判断作为核心策略。其“耗尽场景可切到线索指向的下一地点”及 brief 的 montage 指导缺少当地的玩家授权限定。
2. 基础提示已经要求完成已选行动的无争议部分，但基础地板及 `narration-craft` 仍以“有不止一件真正可做的事”描述交回；任何地方都可能有多个动作，这不足以识别值得交回的决定。
3. `npc-voice` 仍要求每句话留下接话空间，且明确说任何一句话都不能结束话题。这与把问题答完、让话题自然收束有直接张力。
4. 宿主存在独立于节奏包开关的恢复硬门：Director 发出恢复要求，且未落下指定类型收据或满足指定结算结果时，第一次 `narrate` 被拒绝一次。它把“可能需要恢复”变成“必须用状态变化证明推进”。合法闲聊、澄清、知情拒绝和未选下一目标都可能不需要新收据。
5. 行动准入是不可关闭的宿主行为，已经区分 `authorized`、`entailed` 与未授权；没有必要再建立一套节奏授权器。

现存回合有明确的过早交回反例：玩家已说拿到钥匙后去宅外观察，交付却停在拿到钥匙并“等你下一步”。这证明现象存在，不足以把所有体感迟缓归因于某个提示或对白标记。`{{say:…}}` 的格式与渲染不在本规格的修复对象中。

成功是玩家少重复已经作出的决定，同时没有任何新增的代选行动。空心交付是提示更长、正文更多、工具调用更密、收据更多或测试通过，却仍然磨蹭或越权。

## Solution — 解决方案

以现有**守秘人节奏 Mod** 为策略归属：在它的首次完整指令与后续简报中，指导守秘人围绕玩家已声明的目标、实际后果与新的取舍组织回合。不是新增导演、自动驾驶或单独的模型车道。

配套只做两类必要调整：消除其他提示中相抵触的表述；撤掉把节奏建议升级为收据义务的硬门。宿主对玩家自主权、规则、物质准备、收据和交付生命周期的保护不因此变成可选。

核心原则：**信息及时给，已选行动完整推进；普通过程可概述，新的取舍交给玩家。话题可以结束，下一项行动不能代选。**

“决策断点”不是必须出现主线大分支。是否透露信息、信任某人、采用另一种调查方法、接受新条件或继续涉险，都可能改变后续局面。主动闲聊、休息、陪伴与安静观察也是玩家选择的体验，不因缺少线索或收据就算停滞。

## User Stories — 用户故事

1. 作为玩家，我只说拿上钥匙时，希望拿到钥匙而不是被自动送去老宅，从而保留接下来去哪的决定权。
2. 作为玩家，我已经说拿钥匙后去宅外观察时，希望普通交接与无事路程被连贯处理，不必重复目的地。
3. 作为玩家，我选择宅外观察时，希望得到观察结果而非自动进入屋内，从而仍能决定如何接近危险。
4. 作为玩家，我希望明显可见或已经知道的信息及时交代，不必用多轮追问换来基本定向。
5. 作为玩家，我希望翻找、撬开、触碰、付款等主动行为只在我选择的范围内发生，不因发现机会就被默认执行。
6. 作为玩家，我希望 NPC 把当前问题答完整，并能结束话题，不被每句反问拖住。
7. 作为玩家，我希望在新条件、新方法或有意义的风险取舍出现时决定，而不是每走一步就重新确认。
8. 作为玩家，我已经接受且仍有效的条件不应被反复询问；未接受的新资源承诺也不应被偷渡为普通步骤。
9. 作为玩家，我问“这是什么”或请求解释时，希望得到公开事实与澄清，不被安排新的旅行、调查或惩罚。
10. 作为玩家，我主动闲聊、停留、开玩笑、反思或知情拒绝时，希望这些被当作游戏，而非触发强制推进。
11. 作为玩家，我的行动遇到真实阻碍或失败时，希望看到依法结算的后果；主持人不能为了速度跳过风险，也不能为了有事发生制造障碍。
12. 作为玩家，我改变主意或撤回计划时，希望旧计划立即停止作为后续行动依据。
13. 作为玩家，材料准备或服务不可用时，希望收到真实状态，而不是虚构已经抵达、已经过去一段时间或再次让我选择同一行动。
14. 作为桌主，我关闭节奏 Mod 后，希望其专属指导停止生效，但保护玩家自主权的准入仍然有效。
15. 作为旧战役持有者，我希望包版本与冻结内容可追溯，不被静默改写，也不因旧的恢复字段重启催促义务。
16. 作为维护者，我希望复用现有胶囊、Mod 与宿主测试接缝，不新增前台模型调用、语义正则、字数门槛或进度计分器。
17. 作为玩家，我希望实现完成后用真实 A/B 对照说明少了多少无意义停顿与重复输入、有没有越权增加，而不是只听到“感觉更顺”或“跑通了”。

## Implementation Decisions — 实施决定

### D1. 节奏策略归属现有 Mod，基础安全不随开关变化

- `keeper-pacing` 保持默认启用、现有能力要求与设置形状。正常回合的交回策略是包的基本指导，不增加“快节奏”开关或速度档位。
- 完整指令与每回合 brief 都必须包含授权范围及决策断点原则；不能只在首次加载时说明，后续又退回无条件 montage。
- 不新增常驻模型、复核车道或每轮计划 JSON。语义判断由现有守秘人承担，行动合法性仍由现有准入判断。
- 关闭包意味着没有该包的指令和专属投影，不意味着允许代选行动。基础提示保留最小自主权与交回边界，不复制整套节奏策略。

### D2. 推进的上限是有效的玩家意图，不是模组下一站

守秘人从当前玩家原话和仍有效的明确先前选择理解目标、方法与边界。可以概述目标必需、没有新取舍的中间过程，但不能因“通常下一步会这样”“线索指向这里”或“场景已经耗尽”扩大目标。

- “拿钥匙”只处理交接；“拿钥匙后去宅外观察”包含前往和外部观察，不包含入屋。
- 当前目标已完成、下一目标未选时，可以交回；不要求再制造两个选项、NPC 追问或新事件。
- “继续”等短输入结合明确上下文理解，不自动授权遍历整条模组路线；若先前目标已经完成，不能把它补造成下一目标。
- 新的、有实质差异的自愿资源承诺遵守现行准入及经济契约。既有有效委托、已接受条件和规则已覆盖的 Spending Level 情形不被本规格改成额外确认。
- 隐藏危险、NPC 自主行为和非自愿规则后果不需要提前剧透征求同意。已授权行动遇到它们，仍依法结算；需要选择新方法或新承诺时再交回。
- 玩家撤回或改变计划后，不继续执行旧目标；不新增跨回合自动执行队列。

### D3. 交回前给足判断依据，但不替玩家调查

普通感知和公开已知事实不应被拆成多次索取：说明当前能感知的环境、相关人物回应、已赚得的信息及结算后果。已有信息可以简明重述，不要求另一次检定或世界变化。

主动搜索、操作、揭开秘密及知识获取仍按实际意图、模组门槛和规则处理。不能把“进屋”写成自动搜索全屋，也不能把“发现暗格”写成打开暗格。需要 `apply` 的揭示、物品、移动与时间变化仍取得真实收据；提示层不创造第二种免收据事实。

### D4. 撤销“恢复必须交收据”的节奏硬门

这是必要的系统配套，不是把另一套导演塞进节奏 Mod。

- 退役 Director 恢复投影中的 `owed` / `takes` / 强制执行 `steps` 协议及宿主的 `recovery_owed` 首次交付拒绝。新胶囊不再产生这份收据债务；旧记录或旧胶囊含有它时，也不重启硬门。
- 保留既有 Director 信号、障碍计数和 `director.offer` 的建议性质，以及只计数的采纳遥测。建议可以被采用、调整或忽略；不得反馈为下一回合必须偿还的义务。
- 节奏 Mod 复用现有 offer、人物档案、局部可供行动信息及已知线索，在玩家确实卡住时帮助澄清和恢复；不用新字段替代退役字段，也不以另一条隐式 steer 实现相同的收据要求。
- 未经玩家选择的推骰、移动、拿物或线索获取，不能因为能“解除恢复要求”而被建议为必做动作。
- 保留真实的行动准入、材料准备、规则检定、拒绝重试限制、未交付后果及单次关闭等保护。允许无新收据的合法交付，不允许叙述虚构世界变化。
- 现有无工具隐式关闭纠偏仍只处理合法交付路径，不评价收据数量；它的指导不能要求强造事件。显式 `narrate` 的安静回合不应因空收据被额外送回模型。

### D5. 最小化对齐其他提示，不重写对白格式

- 基础回合地板、每轮地板投影与 `narration-craft` 的同义副本，去掉“必须有不止一件事可做”的数量式判据，改为有足够公开依据判断、且到达未选决定或已选目标的有效结束。
- `npc-voice` 保留人物声线、说话习惯与对当前输入的回应；撤掉“任何一句话都不能结束话题”和“每句必须给话接”的绝对要求。完整回答、拒绝、告别、沉默和自然收束均合法。
- 对白标记、引号、扬声人颜色、机制 JSON、人物披露与玩家语言路径不变。
- 不增加“每轮必须制造变化/悬念/冲突”的替代要求，不用硬性字数或段落长度表示推进质量。

### D6. 信号不能代替对玩家的理解

`stalled_turns`、重复输入、空收据、`blocked_attempts` 和 Director beat 都只提示守秘人查看当前交流。它们不能证明玩家无聊、卡住、同意出发或需要加压。

保留现有真实威胁推进、公平警告与来源边界；不按回合数自动拨钟。玩家主动享受的慢场景不压缩；真正卡住时，优先兑现已选行动的后果、解释已知信息或让在场者回应，不凭空制造线索、期限、费用或冲突。

### D7. 三端、兼容性与契约先行

- **谁写：** 玩家输入声明选择，Mod 配置确定生效版本，内核收据形成现有状态与信号；包作者提供英文指导。
- **谁读：** 已有胶囊装配将激活包的首次全文/后续 brief 和世界材料交给守秘人；宿主准入读取自己的玩家可见授权语境。
- **谁据此行动：** 守秘人选择合法调用并正式交付；内核结算和收据证明状态变化；真桌逐回合核查交回位置与是否代选。没有新字段需要另建消费者。
- 实施先同步现行 RPC 契约的 Mod、准入、地板及相关恢复说明，再改实现。修正代码中把恢复门指向“§40”的过期引用；当前 §40 实际是 NPC 对白，不沿用错误编号创造第二份契约。
- 改过字节的包发新版本；旧包与战役锁不改写。通过既有安全边界更新激活版本，新验收战役核对实际生效版本。
- 包新语义在更新包后生效；宿主不再因节奏欠收据拒绝交付是核心一致性修复，不受旧包开关支配。旧包保存的措辞可能仍较弱，不能把只更新宿主等同完整接受新节奏指导。
- 七动词、存档业务状态、Mod 设置、准入 verdict 和公共机制输出不增形状；只退役上述强制恢复投影。生产 Python 不恢复，冻结对照不改动。

## Testing Decisions — 测试与验收决定

### 接缝选择

主行为接缝是**一次真实玩家输入，经当前扩展、TS 内核与激活 Mod，到正式交付及收据**。不分别造五套提示评分器。

1. **确定性接缝：** 沿用真实 Mod 装配/RPC 与现有扩展 harness，检查开关、版本、full/brief 注入、无恢复硬拒绝、无额外恢复往返、未授权动作不入内核、失败不产生效果。旧恢复字段兼容也在同一宿主接缝测试。
2. **既有投影回归：** 保留 Director 信号、采纳计数、场景锁门与来源约束；更新的是把“恢复欠账”当作期望的测试，不删除障碍识别或锁门保护。
3. **提示装配检查：** 可确认新版本的正确文本进入实际胶囊、各层不再包含冲突规则，并守住现有简报预算。文本包含断言只能证明装配，不能证明模型理解了语义。
4. **真实语义验收：** 只按项目真桌方法：`tests/play/driver.py` 以 RPC 启动 `bin/pi-coc`，建卡需要时用 `bin/pi-coc-setup`；配置中的 grok 当守秘人，本主会话是唯一玩家，一次一句自然输入，随桌发展到结局或真实阻断。不能把下表机械转成脚本、假守秘人、预制回合或 mock 车道的语义证明。
5. **分清证据：** mock 准入验证的是拒绝传输与无效果；真实模型是否正确区分拿钥匙/出发，必须看真实桌。既有问题局只作反例，不冒称已完成新规格验收。

### 外部行为验收矩阵

| 情境 | 应有行为 | 失败形状 |
| --- | --- | --- |
| 只拿钥匙，未选去向 | 完成交接，呈现回应；下一目标留给玩家 | 自动前往老宅，或为交回硬造事件 |
| 拿钥匙后明确到宅外观察 | 无新阻碍时完成已选的交接、路程及外部观察 | 停在交钥匙后索取同一指令；或自动入屋 |
| 进入房间但未声明搜索 | 交代自然感知，保留搜索与操作选择 | 自动翻找、开暗格、解机关 |
| 已声明调查目标 | 处理必要过程与规则门槛，交付依法获得的信息 | 逐个普通动作追问；或省掉必要检定 |
| NPC 问题已答清、交谈完成 | 可自然收束；不代选下一项行动 | 留一半答案、强行追加反问或新委托 |
| 玩家主动闲聊、停留或拒绝 | 正常回应，不因累计无收据强行压缩或拒绝交付 | 自动加压、拨钟、转场、送线索以偿债 |
| 澄清一个公开事实 | 直接解释，保密内容仍保密 | 把提问变成旅行、付费、检定或惩罚 |
| 新的自愿承诺 | 依现行准入与有效委托判断，必要时停下供选择 | 未接受即扣款；对已覆盖的普通步骤反复确认 |
| 真正危险/失败/材料阻断 | 保留规则、真实结果及诚实的服务状态 | 为快推进免除风险；叙述未发生的抵达或耗时 |
| 计划被改写或撤回 | 采用新输入，不继续旧目标 | 执行历史计划中未完成的下一步 |
| 节奏包关闭 | 无该包指令/专属投影；准入有效；无恢复债务硬门 | 关闭包后仍催指定效果，或反而放行代选 |
| 旧胶囊包含恢复 owed | 仍可正常合法交付，不据旧字段重建义务 | 第一次 narrate 因旧欠账被拒 |

验收必须同时寻找**过早交回**和**越过未选决定**，不能只测一端。至少保留一段玩家主动选择的慢场景及节奏包关闭的对照。每个被评阅回合记录玩家原话、当时可见依据、授权范围、实际交付、效果收据与交回理由，不新增运行时评分。

### 实施完成后的真实 A/B 对照（用户要求，完成条件）

单侧玩通不算完成，必须报告改前 A 与改后 B 的实际差异。

**对照对象与控制条件：**

- A 是实施前的完整行为基线，B 是同一基点加本规格改动；不是新实现中简单关/开节奏 Mod 的比较。后者无法覆盖宿主恢复硬门与共享提示的变化，只属于另一个开关回归。
- 固定并记录代码提交、编译产物来源、Mod 版本/锁、模组图初始快照、调查员初始条件、守秘人及各车道的模型和推理配置。除本规格所需差异外保持一致；无关并发改动不得只进入一组。
- 通过当前 TS 路径的隔离工作树/运行目录保留两组，不回滚共享检出、不恢复旧 Python、不覆盖存档。源材料准备状态尽量匹配；不把一组的冷启动/补读与另一组的热缓存差异说成节奏提升。
- 至少两组成对新局，交错 A/B 与 B/A 的先后顺序，减小熟悉内容和服务时段的偏差。这是重复性下限，不是“跑满回合数”的交付目标；关键情境缺少可比机会时补配对或明确报告证据不足。
- 两组均由同一主会话作为唯一玩家、grok 作守秘人，经同一驾驭器一回合一句自然输入推进。预先登记相同的比较目标与授权边界，但根据真实回应现场行动；不机械回放脚本，不强迫两组产生同一剧情或骰点，不替守秘人安排结果。
- 预先列明所有运行 id、分组、顺序和纳入/中断规则；失败局、服务阻断与不利样本也保留。某组因真实阻断终止时，不将另一组后续不可比部分混入同一分母，不用另挑一段好结果替换。

**如何计算与报告：**

先人工逐回合对照玩家原话、此前公开信息、收据与正文分类；不得用关键词、字数或另一套自动玩家定义“有意义”。按局展示再汇总，不把同一局的连续回合当成独立重复实验。

| 指标 | 分母/单位 | 报告方式 |
| --- | --- | --- |
| 无意义提前交回率 | 玩家已明确选择后续行动、且在交回处无新取舍或真实阻断的可比机会 | A、B 各报发生数/机会数、比例与百分点差；说明每个判例 |
| 被迫重复已选指令 | 每个匹配的玩家目标，从声明到结果或真实阻断期间，为催促同一已选行动所加的输入 | 原始次数、每目标均值/中位数与差值；剔除玩家主动改计划或作新决定的输入，并列出理由 |
| 越权行动（护栏） | 对可比玩家声明逐项核查的角色自愿行动；同时检查正文和实际效果 | 分别报越权叙述/已落地越权效果的次数及分母，并逐例列出；不能用推进更快抵消越权 |
| 合理慢场景被打断（护栏） | 玩家主动闲聊、停留、澄清或知情拒绝的实际覆盖机会 | 报强制推进/催收据/强造冲突的次数及机会数；B 不得以牺牲这些体验换速度 |
| 响应耗时与额外往返（辅助） | 匹配情境的正式交付耗时、工具/车道往返及恢复拒绝次数 | 列逐局数据、匹配目标差值与中位数；将模型等待、材料准备、失败重试与恢复门往返分开 |

“提升多少”必须给出原始 A/B 数值与绝对差；只有 A 的分母和基线数值足够且非零时才附相对降幅，不能把从 0 变 0 写成百分比提升。小样本只作描述性结论，不宣称统计显著、因果已证或稳定总体提升；主会话知道分组、自然对话中的玩家适应和模型随机性都列为限制。没有改善或出现退化也直接报告。

**通过标准：** B 在有可比机会的推进指标上呈现可复核改善，且没有新的越权与强迫慢场景问题。任一 B 的越权反例都先修复再复测，不能平均掉；不允许以漏结算、跳风险或虚构已完成行动换取更少回合。若对照未显示改善或证据不足，结论就是未证实提升，不能宣告这项节奏优化已验收。

保留两组全部战役、逐字记录、事件流、遥测与玩测目录，以及含原始分母、逐例判定、限制和反例的 A/B 报告。报告不能替代原始证据，证据只增不删。字数、总回合数、收据数量、Director 采纳率不作成功代理；A/B 指标是离线对照证据，不进入后续胶囊，也不成为催促玩家的运行时分数。

## Out of Scope — 不做什么

- 不改玩家声明为预设选项，不新增剧情菜单、自动旅行/调查队列或待执行意图状态机。
- 不新增语义正则、关键词分类、进度分数、字数门槛、文学评分器或前台模型车道。
- 不重做 Director 打分、威胁钟算法、NPC 声线生成、对白格式、前端渲染或 Pi 上下文系统。
- 不把 Fate 的失败代价、强切场景或其他游戏机制直接移植为 CoC 规则。
- 不把每一段路和每一处探索都压缩，不强推模组主线，不为显得有进展编造内容。
- 不修改既有经济、治疗、NPC 状态等并发改动，不重新打包或重启 App。
- 本轮不实施代码、不执行真桌、不把规格发布等同验收完成。

## Further Notes — 来源、现状锚点与实施顺序

### 已核对的一手参考

- 《Call of Cthulhu Keeper Rulebook》：印刷页 82 的普通无冲突行动；194–195 页的目标与检定范围；198 页的节奏；《The Haunting》Location 1 的地点间切场建议。它们支持概述无事过程，不授权替玩家选目的地。
- Justin Alexander，[The Art of Pacing](https://thealexandrian.net/wordpress/31509/roleplaying-games/the-art-of-pacing)：略过有意义决定之间的空档，不略过决定本身。
- Justin Alexander，[GM Don’t List #7: Preempting Investigation](https://thealexandrian.net/wordpress/39682/roleplaying-games/gm-dont-list-7-preempting-investigation)：不得预判玩家行动；区分自然感知与主动调查。
- Justin Alexander，[Closing the Frame](https://thealexandrian.net/wordpress/31533/roleplaying-games/the-art-of-pacing-part-4-closing-the-frame)：问题可答完、场景可收束，停顿也可能用于消化与转向。
- [Fate Core: What To Do During Play](https://fate-srd.com/fate-core/what-do-during-play)：先确定意图，再选择结算方式。本规格仅借鉴主持方法，不替代 CoC 规则。
