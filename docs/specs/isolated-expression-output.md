## Protocol and ownership

The launcher enables isolated expression for hybrid play. The engine announces the capability to the kernel extension. After actual effects settle, the Keeper emits `{{compose}}` and one JSON object with `scene`, `narrative_content`, `npc_turns: [{speaker, intent, personality, emotion}]`, and optional `writing`. The host supplies `play_language`; arbitrary history, private capsules, tool transcripts, Mods and the Keeper system prompt do not enter the author's request. `{{reference}}` keeps the existing direct OOC path. The host buffers composition privately; only the fresh author's public prose opens the existing delivery stream.

The author uses the existing runtime reader adapter with read/write/edit/bash available, task-local confinement, explicit model/off effort and retained task/events. Its instruction covers writing only. It has no game tools, checker requirement or coverage assignment. It returns `{{public}}` followed by prose. Failure preserves evidence and any exposed prefix; it does not trigger semantic repair or quietly fall back to Keeper prose. A publication retry reuses the accepted text and never re-settles actions.

The optional `writing` field accepts a string or a JSON object, retained unchanged. Both first scene-transition failures used named writing preferences while the initial parser accepted only a string. Existing prospective heard-knowledge entries that have no actual matching speech remain pending, as before; this change adds no semantic matching or inferred hearing.
