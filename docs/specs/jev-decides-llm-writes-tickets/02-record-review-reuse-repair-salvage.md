# 02 — Review reuse per unit, targeted repair, salvage of an interrupted author

Measured waste (Blood05): 3/29 refused claims cost a 156 s re-author plus a full re-review; pages 15–16 were authored four times in one campaign after interruptions.

Scope:
1. Unit-level review cache identity (§150.2.1); `/coverage` stays whole-candidate.
2. Targeted repair round (§150.2.2) with the host's byte-identity check and full-round fallback.
3. Salvage on resume (§150.2.3).
4. Accounting fields on reading rows (§150.2.4).

Tests at the reading-service job runner (fake runtime) and reviewer (fake `run`) seams: an edit to one record re-runs only its unit(s) and `/coverage`; a refusal without `missing` produces a repair brief listing only refused paths and a re-review that reuses the unchanged units; a repair that alters an unrefused record is refused and falls back; a review with `missing` runs the full round; an interrupted attempt with a checker-passing draft and all required pages delivered skips the author; one missing delivered page does not. Each case must fail under a mutation of its fix.

## Comments

### 2026-09-28 implementation (branch `claude/jev-reach-20260928-02-review-reuse`)

What changed (contract: §150.2 implementation decisions 150.2.1-150.2.4 were added under §150.2):

- **B1, per-unit reuse** (`extensions/module/reader-review.ts`). `reviewUnitIdentity`: a fact unit is keyed by protocol, instruction version, source SHA, native extraction version (`sourceTextVersion`, new `extractionVersion` option), model, the focused input's hot task fields (minus `required_review`/`review_scope_pages`), its records exactly as written with the pointers each owes relative to the record, the focused input's known and candidate context, and the cited pages. `/coverage`, guidance and answer keep the whole-candidate identity exactly as before; round bookkeeping (`repair`, `must_view_pages`, `review_retry`, `commands`) never enters the fact identity. Because positions are not in the identity, a retained fact review stores its record roots and its rows move to the records' current positions on reuse; rows about records outside the unit are dropped. Each graph verify round writes `review-plan.json` (candidate + review digests, units with record digests); a later round's verify keeps the grouping of every previous unit whose records all survive byte-identical (`carriedReviewUnits`), otherwise one deleted claim reshuffles every later batch. `review-plan.json` joins the reader child's host-owned files (`reader-context.ts`).
- **B2, targeted repair** (`extensions/module/targeted-repair.ts`, wired in `reading-service.ts` `runJob`). Decision: refused = what the gate's `checkReview` would refuse (not supported and not a contest/advisory finding); targeted only for opening/detail, only for a review bound to the candidate via the plan digests (own attempt, then `resume_from`), never for `resumed.reread`, and only when every refused path is in an existing node or claim; `missing`, a non-record refusal or no bound review is `full`. The author gets `task.repair.kind = "targeted"`, `refused` (path, root, verdict, reason, source_refs), `pages` (refused records' cited pages + a source unit's assigned pages, which the checker requires) and `TARGETED_REPAIR_ASK`; the native driver (`runtime/jev/source-reader-driver.ts` `locate`) projects exactly those pages with their native text. Host check `checkTargetedRepair` (byte-identity by canonical JSON at any position; orphaned claims of a removed refused node excepted; at most one replacement per refused record; replacement nodes keep a refused id; `ready_nodes`/`node_refs` lose exactly removed ids; `critical` renumbered to follow kept records; other shard fields unchanged). Refused: `targeted_repair_refused` row, candidate and pending needs restored, and the same round's read runs again as today's full repair (targeted pass logs to `read-<round>-targeted.jsonl`), so the two-round bound is unchanged.
- **B3, salvage** (`extensions/module/read-salvage.ts`). On resume with no `read-complete.json` in `resume_from`: own job only (`packet.json` job_id), not reread/review_retry/repair, purposes opening/detail/answer (guidance excluded: its guidance/public-field checkpoint digests). Delivered pages = host full pages with matching image bytes + full-page `pdf` observations of successfully included tool calls, from every `read-*.jsonl` + `.images.jsonl` of the attempt. Non-empty draft + checker ok + every `required_view_pages` delivered → checkpoint `{…, salvaged: true, salvage: {source_attempt, required_view_pages}}`, review follows. Rows `salvaged` / `salvage_refused` (reason empty | checker | pages, delivered/required/missing pages).
- **B6, accounting** (`extensions/module/reading-accounting.ts`). One `job_accounting` row per job run: author_ms, review_wall_ms, units_run, units_reused, jev by family (children's `jev_transport` traces in this attempt's author and reviewer dirs, plus host rows written as `{event: "jev_decision", family, attempts, ms, input_tokens, output_tokens}` on the job's rows — the shape ticket 03 should use), salvaged, repair, need (slot for 150.4; nothing sets it yet — ticket 04 sets `accounting.need`). Plus `repair` rows (`targeted | full` with refused roots/pages or reason).
