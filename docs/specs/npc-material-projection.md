# NPC 材料投影：给守秘人「这个人此刻想说什么」，不是条目清单

日期：2026-09-25。Status: `needs-info`（等用户决定落在哪条线上，见 §4）。前置：[prose-mod.md](prose-mod.md) 已落地于 `0.9.5a@44ec2022f`。

## 1. 问题

prose-mod 的 A/B 真桌（`.coc/playtests/prose-mod-acceptance/REPORT.md`）里，六类缺陷有五类 B 桌更少，只有「NPC 任务提示腔」两桌持平 4:4。逐段看，它不是叙述在交还回合时列菜单，而是 NPC 台词本身在念清单：

- 诺特在 t1 和 t15 都把去处（报馆、图书馆、档案厅、邻居、疗养院）并列报一遍；
- 档案厅办事员在 t7 都会列郡法院、州法院、中央警署。

这些内容来自模组：诺特的委托本来就写着三处去处，办事员的 `hides` 写着「刑事卷宗在县/州/联邦或中央警署」。守秘人念它们，是因为它们以**条目**的形状到他手里：`present[].wants`、`hides`、`keeper_note`、`history.tried`、`where.exits`、`director.offer` 每一项都是「一个人 + 一串可选项」。文风指令压不住条目，模型对条目的自然反应就是逐项念出来（2026-08-14 的教训：给 KP 平铺信息面板不改变行为，给他一条链才改变，见记忆 `give-the-kp-a-chain-not-more-panels`）。

## 2. 方向

不加文风句，改投影的形状：

1. **一个人一句话。** `present[]` 里的人在这一回合投影成「此刻他想从这段交流里得到什么、愿意给什么、不肯给什么」的一句话，由内核从 `wants/fears/hides/toward_party/history` 机器拼装（不是模型写），条目原文留在 `look focus=npc` 里按需读。
2. **去处不进人物档案。** 一个 NPC 知道的去处属于 `where.exits` 与 `mods.thread`，人物档案里不再重复；守秘人要让 NPC 指路时去读场景，而不是从人物条目里抄清单。
3. **`director.offer` 只给一条。** 三条并列的 offer 是一张菜单；只投影得分最高的那一条，其余留在 `because`。

## 3. 验收

同 prose-mod §7 的方法：同模型同 15 句再跑一桌 C，对比 B；只看第 5 类是否降，其余五类不退步；口吻列队不降。

## 4. 落在哪条线

现在装着并在运行的 App 是从 `claude/integ-single-loop-20260923@e8a883604` 打的，比 `0.9.5a` 多 362 个提交，其中大量改动在胶囊投影与 NPC 材料上（SL-56「NPC 材料从不占住回合」等）。本 spec 改的正是这一片。在 0.9.5a 上做会和那条线冲突，在那条线上做又不是主线。需要用户先决定两条线怎么汇合，再开工。
