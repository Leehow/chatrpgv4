# 22 — 玩家的话只进说给他听的那个人的处境包；开场的生成行动用玩家语言

## 证据（真桌 `npc-acts-b`）

- T1：玩家对克兰说「这活我接了。钥匙和钱给我，我先去环球报翻翻旧报纸。」书记员同一回合把他移到环球报；亚瑟被作用触发生成，处境包 `happened` 的最后一条永远是玩家这回合的原话（工单 01 的实现：kernel 没有 addressee，于是「总是带上」）。生成器于是写「亚瑟把钥匙从抽屉里拿出来……又数出几张钞票推过去」——把克兰的委托演到了亚瑟身上，KP 照着写进了正文。
- T0（开场）：克兰的生成行动是英文（「Crane clears his throat and asks 林默…」），这桌是 zh-Hans。

## Scope

1. `npc.situation` 接受可选 `addressed: boolean` 与 `declared_before_move: boolean`（宿主从 compile 的 addressee 与本回合落地的 move 顺序得出，§143.4 的扫描已持有这两样）：玩家原话只在「他被点名，或他在对话中（工单 21），且这句话不是在移动到他这里之前说的」时放进 `happened`；否则放一句代码拼的「the investigator has just arrived here」之类的结构句（或什么都不放），不放原话。
2. 生成车道的输入永远带 `play_language`（从战役读，不从会话状态读）；查清 T0 开场那次为什么是英文（开场回合的 run 是否在 play_language 可读之前起步），修掉并加用例。
3. 契约 §143.1 与 §143.2 各加带日期的注，§143.21。

## Acceptance

- pytest：同一回合先 move 再到场的人，`npc.situation`（带 `declared_before_move: true`）的 `happened` 不含玩家原话；被点名的人含。
- ext：开场回合的生成请求里 `play_language` 是战役的语言（夹具断言请求体）。
- 变异：把原话恢复成总是带上 → 第一条逮住。

## 落地记录（2026-09-26）

- `npc.situation` 接受 `addressed`、`declared_before_move`；收尾句：移动前说的 → 「刚到他这里」的结构句；说给他的 → 原话；否则不放。两项都缺省时行为不变（战斗里他自己的回合不传）。
- **开场英文不是缺语言。** `campaign.json` 建局时就有 `zh-Hans`，比开场那次行动早四分钟，步骤也传了。模型面对的是一包只有宿主英文和书里英文 `who`、没有玩家原话的材料，跟着它写了英文。现在输入里在语言码旁边加上英文名（`play_language_name`，取自 `Intl.DisplayNames`，不是表），车道说明写明「处境包的英文不决定你用什么语言」。能不能扭过来要看 B2。
- **合并复核时我改窄了的条件（我自己工单写窄了）：** 按工单原文，没被点名、也不在对话中的人就不给原话——第一次接触时玩家揪住诺特说「钥匙交出来」不带名字，他被作用了、包里却没这句话。改成：**只有 compile 点名了别人**才不给（`declared_before_move` 是另一条证据）。加了两条用例（不带名字揪人 → 原话在他包里；对埃德娜点名说话、同回合诺特也被作用 → 只进她的包），变异（恢复成点名或对话中）逮住第一条。契约 §143.21 加了带日期的注。
- **放宽后挖出的老缺陷：** 开场回合没有玩家原话（`player_text` 为 null），但 `flat()` 套的是 `string()`，把 null 渲染成 Python 的 `"None"`，于是开场的包里一直有一句 `托马斯·海斯 (investigator) declared: "None"`。22 按原文把不相干的人的原话拿掉，恰好把它藏住了；我放宽条件后开场用例立刻失败。`flat` 改成缺席即空串，开场用例守着它。B 桌开场克兰那次行动写成英文，这句假话可能也有份，B2 桌看。
