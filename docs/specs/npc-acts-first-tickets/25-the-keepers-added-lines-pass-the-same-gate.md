# 25 — KP 替桌子的行动添的台词，也过「同一个目的」的闸

## 证据（真桌 `npc-acts-b2`）

- 「带纸来 / 带公函来」：T5 生成、T6 生成（都在执行中：关灯赶人），T9 生成器那回合被重问一次后写的是**不说话的动作**（揣钥匙、按着开关瞪你），KP 渲染时自己给亚瑟加了台词「楼要锁了。昨天的话不变：带纸来，带人来，随你挑」——同一目的第三次出现，出自 KP 添的话。
- B 桌的四次重复全在 KP 写的亚瑟里（当时生成步骤不跑）；B2 生成器没有重复过。漏口是：§139.5/§139.14 的两道闸只看生成的行动，KP 在正文里替这个人加的台词不过闸。§139.7 只说「正文渲染桌子的行动」。

## Scope

1. **交付时的语义闸（结构触发，Jev 判）。** 这回合正文里说话记号归属于某人（`who.npc`）的台词，若这个人这回合有桌子的行动（或在对话中），把他的台词与他账上**没有结果或已放弃**的行（`done` 里 attempted/abandoned，§139.14 同一套问法：同一件事、同一个目的，不管手上做什么、话怎么说）问一次 Jev。命中 → 交付被拒一次，fix 点名「<他> 在第 N 回合已经说过 <那一行>，没有结果；渲染这回合他的行动，不要让他再说一遍」；第二次交付放行（绝不卡死交付，§139.10/§139.17 同一条通道）。
2. 不读散文做判断：台词取自说话记号；判是不是同一个目的交给 Jev；每回合至多一次 Jev 批。
3. `prompts/keeper.md` 的 present 段加一句同义的话（卡片上已有他的 `history.intents`）。
4. 契约 §139.24；§139.7 加带日期的注。
