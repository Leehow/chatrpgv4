# 15 — 宣布要做的事和做它是同一条线；只有骰子和桌子能把它结成 done

## 证据（真桌 `npc-acts-c3`，门反锁、十回合、挨四拳）

诺特四次生成的行动全在电话上：T5「抓起听筒拇指压叉簧」「把听筒死死按在电话机上不出声」、T7「抓起听筒冲他喊：再碰我一下这电话就摇到巡警那儿去」、T10「往后躲，把听筒举在两人之间挡着，另一只手按在电话机边」。正文里 T3、T5、T7、T10 四次说要叫警察/楼上的太太会去叫巡警。电话从头到尾没有摇。按用户口径这就是「同一句威胁换说法反复说、从不执行」，只是从「喊人」换成了「电话」。

两道门都按设计跑了、都没拦住：
- 语义门（§143.5）问的是「这句和最近几行是不是同一个**动作**」——抓听筒、按听筒、举听筒、喊话，物理动作各不相同，Jev 只在 T7 判过一次同一（重问一次，第二次换了措辞就放行）。
- 欠账门（§142.7）要的是「有结果」：T5a 被 KP 用一条线索的 `intent_ref` 结成 `done`，T5b 被 KP 结成 `abandoned`，T7「喊出威胁」被 KP 结成 `done`（喊是喊了）。结构上每条都有结果，于是包里的 `done` 段告诉生成器「电话的事都办完了」，它就再来一次新的电话动作。

根子有两个：**同一件事的定义是动作而不是目的**；**宣布可以被记成 done**。

## Scope

1. 语义门的问题改成问目的：「这句行动和他最近几行里的哪一行，是在做同一件事、为同一个目的（不管手上动作是否一样）」——选项仍是那几行的原文，仍闭合。一条被判同一的行若上一次是「宣布/威胁」而没有兑现，这次的行动必须是兑现或放弃（生成器重问时包里写清「他已经两次拿电话威胁而没有摇，这次要么摇要么放下」）；第二次仍同 → 结 `abandoned` 并把「放弃了电话」写进包，下一回合不许再出现。
2. 只有绑定的结算（骰子、钟、到场、离场）或生成器的放弃能把一条**生成的**行动结成 `done`/`failed`；`intention_only` 的行动永远停在 `attempted`，KP 只能把它结成 `abandoned`（D7 的否决），不能用一条线索或一句 why 把它结成 `done`。契约 §143.7 与 §142.2 加注；`apply npc {intent_ref, intent_outcome: done}` 对生成的、只有意图的行动改为 `invalid_params`，`fix` 说「a table act that rolled nothing is not done by saying so: abandon it, or let the dice settle it」。
3. 指令文件 `content/setup/npc-act.md` 加一句（不列动作）：拿出来威胁过而没用的东西，下一次要么用、要么放下，不再拿来威胁第二次。
4. 契约 §143.14。

## Not in scope

- 给「打电话报警」造结算路径（钟的开放参数由 KP 起钟，现状不变）；导演层的随机事件。

## Acceptance

- loop 用例（夹具端口 + Jev 夹具）：三回合同一目的不同动作的行 → 第一次重问、第二次结 `abandoned`，第三回合的包里 `done` 段该行状态 `abandoned` 且 `happened` 带「放弃了」的句子；夹具第三次给的行若仍是同一目的 → 第三回合不新开行（`intention_only` 连续同一目的 → 直接 abandoned，不再问）。
- pytest：`apply npc {intent_ref: <生成的 intention_only 行>, intent_outcome: done}` → `invalid_params`；`abandoned` → 通过；骰子结算的行照旧 done/failed。
- 变异：把「目的」改回「动作」的问题措辞不好机械验证——用夹具 Jev 的答案分支测门的行为；把 `done` 拒绝删掉，pytest 逮住。
- C4 真桌重跑 C3 台本：电话/喊人一类威胁最多出现两次，第三次要么兑现要么消失。
