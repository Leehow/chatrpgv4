# 21 — 在对话里的人每回合都行动：触发不依赖书记员落地，不依赖点名

## 证据（真桌 `npc-acts-b`，mystery-house，玩家一直站在柜台前纠缠亚瑟·威尔莫特，不动手）

- 十回合里亚瑟的生成行动只有 T1、T2、T9 三次（T9 还是 `dropped`）。T3–T8 六回合一次都没触发，亚瑟全由 KP 写——于是「要看就在楼下看，灯我给你留着，明早之前看完／这柜台我不会替你挪」在 T2–T5 出现四次，T5 他自己说「我再说一遍」。这正是用户要消灭的重复，只是换到了 KP 的散文里。
- 两个原因（`telemetry.jsonl` 的 compile 行与 bind 行）：
  1. **扫描的前提是这回合有书记员步骤落地**（§143.4 的会话外触发：「玩家声明 settled 之后」）。纯对话的回合什么都没落地（T3、T4、T6、T7、T8、T10 的 landed 为空），扫描根本没跑。
  2. **点名靠 compile 的 addressee**，而玩家当面对他说话时常常不点名：T3 `unclear` 0.52、T4 `unclear` 0.86、T6 `unclear` 0.43、T8 `none` 0.64、T10 `unclear` 0.27。

## Scope

1. **扫描每回合都跑**（会话外），不以书记员落地为前提：在 compose 之前（有落地步骤就在其后），对在场的人判「这回合是否在和他打交道」。
2. **「在和他打交道」的结构判据（不读散文）**，任一成立即触发：
   - 本回合有收据以他为主语或对象（现状）；
   - compile 的 addressee 过闸点名他（现状）；
   - **他在对话中**：上一回合（或本回合早先）他有行动（生成的、KP 写的意图、或台词归属于他——§128 的说话记号），玩家仍在同一场景，且这回合 addressee 没有点名另一个人（`unclear`/`none` 都算没点名别人）。
3. 每回合上限（`max_per_turn`）不变；多人都在对话中时按最近一次行动的先后排。
4. §143.4 改写触发一段（带日期的注），契约 §143.20。

## Not in scope

- addressee 本身的准确率（Jev 的问题措辞），身份重复（§87.7/87.8，在另一条线上已修，合并时带上）。

## Acceptance

- loop 用例（夹具）：一个 NPC 上一回合有生成行动、本回合 compile addressee 为 `unclear`、没有任何书记员落地 → 他照常行动（一条 `npc_act`，trigger `engaged`）；addressee 点名另一个在场的人 → 只有被点名的人行动；玩家离开场景 → 不触发。
- 变异：去掉「在对话中」判据 → 第一条逮住；把扫描恢复成依赖落地 → 第一条逮住。
- 真桌：B2 同台本重跑，亚瑟每个他在场的回合都有 `npc_act` 行（除了被上限挤掉的）。

## 落地记录（2026-09-26）

- 每回合在 KP 第一次模型步之前扫描一次在场的人（有人在场就扫），之后每落地一个书记员步骤再扫一次；不再以落地为前提。
- 第三个触发 `engaged`：内核 `npc.act.options` 新增 `conversation {turn, order, by}`——他在最新已提交回合（调查员仍在那个场景、他也在场）或本回合早先有行动、意图或被说话记号归属的台词。compile 点名别人时不算。
- 排序：被作用/被点名的在前（按胶囊顺序），只是在对话中的按最近一次出场排；上限不变。
- 代价：有人在场的回合每人多一次内核读；每个 engaged 的人要掷一次威胁骰，会消耗种子骰——别的 loop 用例若有 NPC 上回合说过话，骰序可能变。
- 用例：他上回合说过话、addressee unclear、没有落地 → 一条 `engaged` 行且在第一次模型步之前；两人都说过话、compile 点名埃德娜 → 只有她；队伍换了房间 → 不触发。变异两处（去掉 engaged、扫描恢复成依赖落地）各被逮住。
- 顺带修了一个既有竞态：seam 夹具的工作区先于内核关闭被删（ENOTEMPTY 后挂住）。
