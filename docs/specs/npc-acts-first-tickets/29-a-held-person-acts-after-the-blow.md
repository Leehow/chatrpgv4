# 29 — 被扣住的人，在 KP 结算那一击之后轮到行动

## 证据（真桌 `npc-acts-d2`）

T5、T10、T12、T13：玩家出拳，书记员没接（路由/绑定没定下来），留给 KP；§139.25 扣住诺特（`npc_held`，fight_pending），他没有抢先——这是对的。但扫描只跟在**书记员**落地的步骤后面；KP 在自己的模型步里结算那一拳（`resolve` 落地、有打他的收据）之后不再扫描，于是被扣的人**这回合再也没轮到**：他的反应全由 KP 写，连威胁骰都没掷。四回合恰好是最危险的时刻，D10 的意外在这些回合根本没机会出现。

## Scope

1. 被扣的人在这一击落地之后、这回合交付之前轮到一次：KP 的模型步里落地了以他为对象的战斗收据（攻击/伤害/闪避），或声明的战斗动作以任何方式落地，扣住解除；在 KP 下一次写回合的模型步（compose 或下一轮 adjudicate）之前扫他一次（照常掷威胁骰、生成、绑定、执行）。一击始终没落地（KP 没结算）则照旧不行动、记 `npc_held`。
2. 结构判据：只读收据与扣住记录，不读散文。战斗里他自己的回合（forced turn）照旧。
3. 契约 §139.28；§139.25 加带日期的注。

## Acceptance

- loop（重放 D2 T5 形状）：一拳留给 KP、诺特被扣；KP 的 `resolve` 落地一条打他的收据 → compose 之前有一条他的 `npc_act`（trigger acted_on），且只有一条。
- loop：KP 没结算那一拳 → 仍只有 `npc_held`。
- 变异：扣住后的补扫去掉 → 第一条逮住。
