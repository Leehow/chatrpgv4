The current RPC setup path calls `module.prepare` through `ReadingService.prepare` without `purpose: guidance`, so it starts with skeleton and then opening reading. The product UI worker already has a `purpose: guidance` route that can produce small creation material first. The new source-driver implementation must carry this split into the actual RPC setup/host path; merely accelerating navigation inside a full opening request would not meet the user's first gate. This is a source-to-consumer finding, not a finished fix.

The old path prepared the selected scene before asking the first card question, so it provided no useful foreground overlap to exploit.
