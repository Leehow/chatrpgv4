## JEV-OPEN-01：长局整体响应仍慢

**已知事实。** 修复后台车道抢占后，v8 的叙述工具尾部等待已从 v7 的 37.904 秒降到 0.200 秒；最终收据查询只排队 167 ms、自身执行 32 ms。这个具体故障已经关闭。但 v8 整个玩家回合仍耗时 **279.69 秒**，其中运行步骤耗时 188.359 秒，仍高于既有 45 秒软目标。

同一轮 Jev 为 **5 次调用 / 10730 ms / 13 步**，没有耗尽 24 次 / 12000 ms / 40 步额度。因此不能把这一轮的总等待都称作“Jev 超限”。此前 v7 的玩家输入曾在初始化作业后排队 22.052 秒；新队列修复不抢断已经启动的作业，不能假定这部分也消失了。

**已发现但尚未修复的成本。** 当前未公开名字检查会读取长历史；在独立串行只读测量中，即使没有找到名字片段，`table.untold_spans` 也用了 9.114 秒。源码还有每个人分别排序、扫描和规范化历史文本的路径，以及过宽的 preload。日记、口吻和称谓作业的历史读取有实际消费者，不能整批删除。目前尚未量清文件读取、名字计算、锁等待和模型调用各占多少，也未实施新的历史索引或持久缓存。

**下一步。** 用现有 RPC 分段计时，分别拆解输入前准备、状态读取、模型等待和交付；对确认的热点再做内部计时。先明确消费者需要哪些字段，再评估缩小读取范围或复用同一次读取中的确定性计算，不直接增加预算来掩盖成本。

**关闭标准。** 在明确源码、模型、战役规模及运行条件下复测；已定位的高成本路径有前后对照，结果、授权和披露规则保持一致。整体仍慢的部分逐项归属。单个 RPC 变快或尾延迟下降，均不足以宣称整体性能问题已解决。

证据：[v7 修复前 RPC 时间][v7-rpc]、[v8 完整 RPC 时间][v8-rpc]、[v8 决定预算][v8-budget]、[串行只读比较][read-comparison]、[名字读取分析][untold-cost]、[后台作业读取分析][job-cost]。

## JEV-OPEN-02：历史空回复来自哪里

**已知事实。** 原 v32 的 driver 420、1297、1402，各自首次输出和一次补救输出，共六次，都是 `text_start` 后直接 `text_end`，没有文本 delta，结束文本长度为零；输出 token 为 4。这发生在宿主替换消息之前，不能解释为宿主把完整正文删掉了。

**尚未确定。** 上游是否确实返回空消息，还是终止事件中有正文而 Responses 解析器没有补收。旧记录缺少原始 SSE 末尾形状，HTTP 200 本身无法区分两者。新增原始流与归一化结果的长度、事件类型观测已经落地，但尚无新的空回复样本闭合这条判断链。

**下一步。** 出现同类失败时，将同一次请求的原始事件、归一化文字长度和宿主拒绝条件对应起来；区分“没有观测到终止事件”和“观测到终止事件但内容为空”。不记录凭据、正文或私密上下文来凑证据。

**关闭标准。** 定位正文在哪一层缺失，并验证该层的修复或明确失败处理；已结算结果不会因此丢失或重复结算。仅增加日志、正常回合不再出现空白，均不能证明旧故障已修复。

证据：[原始空输出分析][empty-analysis]、[供应商边界分析][provider-analysis]、分类报告 C01。

## JEV-OPEN-03：更早的战斗为什么长期没有退出

**已知事实。** v32 driver 686 仍处于战斗会话。但 745 的公开选择中有 `flee`，746 明确选择逃跑后产生了战斗结束收据，747 已无活动战斗会话。这排除了“内核根本不会结束战斗”的解释。

**尚未确定。** 更早阶段究竟是系统选择没有展示、玩家未回答、回答没有正确绑定，还是另一个会话状态问题。公开选择漏传已修，尚不能据此断言所有历史滞留都由它造成。

**下一步。** 找到最早应当发生状态转换的时点，逐步核对：选择签发 → 玩家可见 → 玩家回答 → 绑定 → 结算与结束收据。只看显式工具名或普通移动叙述，无法判断战斗是否应结束。

**关闭标准。** 明确滞留样本的断点；在当前源码中，玩家作出的合法结束选择能进入内核并正确退出会话。未选择退出时仍保留原规则，不通过自动结束战斗把症状隐藏掉。

证据：分类报告 C02，以及原 v32 的 `turn-745.json`、`turn-746.json`、`turn-747.json`。

## JEV-OPEN-04：剧情反复核验、等待和兜圈

**已知事实。** 旧局出现了大量重复核验记录、身份、权限和回电的交互；其中也有测试玩家持续追问低收益程序的影响。1530–1540 附近的报社移动已找到成功收据，不能继续把这一处列为“叙述移动却未提交”。offer 账中的 1370 次供给全部是 `stated` 规则供给，也不能解释成 1370 个剧情线索都被忽略。

**尚未确定。** 哪些循环来自玩家策略，哪些来自 NPC 回应缺少可执行结果，哪些来自承诺、时间或状态没有兑现；没有证据把它们统一归为某一个 Jev 分类器错误。

**下一步。** 在公开结果层记录玩家目标、NPC 的具体回应、承诺是否兑现或明确失败、时间是否实际变化、是否形成新选项。对重复片段追溯写入、投影和行动的缺失环节，不靠关键词或重复次数强行跳剧情。

**关闭标准。** 代表性的循环有可核对的原因；正常探索中，行动产生有效信息、明确失败或可选择的后续，而非重复复述同一程序。剧情推进依据公开行动和收据，不依赖测试玩家偷看模组真相。

证据：[公开进展分析][progress-analysis]、分类报告 C05。

## JEV-OPEN-05：NPC 准备和续接还有哪些验证缺口

**源码状态。** 已按战斗、步行、司机、乘客分别检查准备度；缺资料时保留已经选定的行动，补齐后走原有规范执行入口。交付、取消、换 run 后失效的处理也已实现。因此这是新增路径的验收缺口，不是“这些代码还没写”。

**尚缺的证据。** 部分 NPC 首击、追逐的准备后续接，以及资料迟到、场景变化、取消、重复刷新等竞态分支，缺少针对当前实现的专项验证。通用测试通过和独立源码复核不能代替这些分支的实际执行。

**下一步。** 在真实 driver 可到达的场景中核查，并复用既有测试。重点看原行动者、目标、方法、角色、车辆与司机链接是否保留；不能把人格文本后台准备与机械属性准备混为一条路径。

**关闭标准。** 资料齐备后只执行一次原动作；未齐备时不抢先写效果、不反复生成新计划；场景、角色或运行归属失效后不重放旧动作。未覆盖的分支继续明确标注。

证据：分类报告 C04、契约 §159.12、[准备度实现交接][readiness-implementation]及[独立复核][readiness-review]。

## JEV-OPEN-06：四类检定尚未完成当前源码的完整自然验收

心理学已在真实 driver 中完成 Jev 选择与内核结算；早期战斗、追逐等路径也有部分真实或机制证据。这些证据不足以宣布战斗、追逐、SAN、治疗在当前完整实现上全部正常。历史 155 个预算样例也没有全部重新验证，不能声称它们都已消失。

| 验收对象 | 需要补齐的实际链路 |
| --- | --- |
| 战斗 | 合法触发、对象与参数、攻击和防御结算、玩家选择、结束状态及公开结果 |
| 追逐 | 合法触发、步行或车辆角色、司机与乘客绑定、准备、推进和结束 |
| SAN | 来源触发、参数选择、内核损失与状态结算、按既有可见性边界交付 |
| 治疗 | 对象与时机、适用条件、参数与效果、不能执行时的正确处理 |

**关闭标准。** 使用当前源码的真实 driver、Flapcode `gpt-6-luna`；保留入口请求 low 及实际调用档位记录，不换 Grok 或 Astra。逐段对应玩家声明 → Jev 判断 → 参数与准备 → 内核收据 → 玩家可见结果。正常免检、未决、拒绝和已结算不能混为一个成功计数；Jev 不可用时不把检定选择交回主模型。遵循当前“真实 driver 与既有测试”的验证边界，不用合成游玩记录代替验收。

## JEV-OPEN-07：原两段剧情和结局目标仍未完成

原目标是玩家不知剧透，像普通玩家一样探索，完成至少两段实质剧情并走到结局。旧 v32 的 1540 次输入不是该目标的完成证明；后来的 V1–V8 是原战役副本上的诊断，也不能转换成新鲜的两章盲玩验收。

**下一步与关闭标准。** 从明确的运行时和战役绑定出发，一回合一句自然玩家输入，保持玩家上下文不接触未发现的模组真相。用实际行动、线索、状态变化和结局收据说明完成了哪些内容；不能以开桌成功、回合数、测试数量或报告齐全替代剧情完成。
