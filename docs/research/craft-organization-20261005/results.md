# Craft organization research report

## Goal and scope

The goal was to test whether the refactored Mod interface can produce connected, human-sounding Chinese prose while preserving agency and the existing source/interface duties. The work is an offline writing treatment, not production equivalence or live acceptance. The measured comparison is **A: current 2.2.7 without optional references** versus **broad B: organized guidance, 2.3.0, without references**. The subsequently adopted **narrow 2.3.1** is a different, narrower composition; it has no exact paired literary estimate.

The author, drafter, and reader work was tool-enabled and satisfied the text-work contract. The explicit model was Flapcode `gpt-6-luna`, low thinking; there was no Astra or Grok substitution. Kernel production sources remain TypeScript; no old Python was restored.

## Design and evidence

Six fixed-result cases were constructed: `arrival`, `quiet-wait`, `door-resistance`, `npc-direct-answer`, `npc-danger`, and `npc-formal-explanation`. Each case received one draft in arm A and one draft in arm B, for 12 drafts total. Each case then received two independent blind reader opinions, for 12 opinions total. There was no regeneration and no best-of selection.

The preference scores were A **7.5** and B **4.5**. Environment scores were A **2.5** and B **3.5**; NPC scores were A **5** and B **1**. These are reader estimates for the broad A/B contrast, not a validation of 2.3.1. The quote audit found 17 claims that passed literal substring checks. Semantic source judgements and prose preferences remain reader/model claims, not machine-certified source errors. Readers sometimes placed stylistic criticism under `interface_defects`; those entries must not be counted as actual broken machine interfaces. In particular, the English word `lifted` in the broad B warning is an observed language defect and is retained as evidence rather than silently repaired.

Selection was separately attempted for the optional references. Six initial Jev attempts timed out without the Node environment proxy. Six same-policy attempts using the existing proxy completed, with the same questions, state, threshold, and deadline, and all selected `NONE`. Consequently there are no C drafts, no production selector, no card-treatment benefit, and no threshold-tuning claim. The six method cards are original optional research assets, not shipped instructions.

## Adoption and provenance

Broad 2.3.0 was not adopted wholesale. Narrow **2.3.1** adopts native-authored paragraph/view organization while retaining exact original fact, closure, and execution clauses. It preserves the original NPC and settings bytes, and leaves global whole/indexed loading unchanged. The package body is **12,995 bytes** versus the **14,245-byte** baseline, approximately an **8.8% package-body reduction**. This is not a claim about total context, token use, latency, or speed.

The original author's JSON syntax was invalid, but the original was retained. A native serialization-only repair preserved its agent string; one native retention refinement and host exact baseline-span composition produced candidates. An initially wrong A freeze read candidate bytes; the baseline was corrected before drafting, while the initial snapshot and preregistration were kept. The runtime identity check found 524 embedded runtime source entries matching source, in a private copy only.

Original NPC and settings bytes were retained because the broad compression showed no NPC advantage in the completed direct-answer votes, included the mixed-language warning, and added explanatory live codas. Retention protects the existing NPC responsibilities and settings semantics while the narrower organization change addresses prose connection. The contract continues to preserve source truth, state ownership, receipts/queued-transaction settlement, one-pass delivery, the existing `say` path, and the global budget/load policy. Prose does not create state, and declared acts are not receipts.
