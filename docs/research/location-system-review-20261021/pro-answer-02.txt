这使我对原判断作出两点调整。

1. 收紧对具体时间失败的归因

上一轮指出“独立 time 行可以阻断主体行动”，这个结构事实仍然成立。但如果据此进一步认定，那些失败主要源于成本独立准入或 Jev 判断方式，现在应降低这一因果判断的强度。

至少需要区分三种情况：

KP 因缺少定义而提出错误类别或多余耗时，Jev 正确拒绝。
KP 提案正确，但准入端缺少必要信息，导致判断不稳。
双方信息完整，仍因活动、成本和准入的划分产生反复误判。

这三种情况需要不同的改法。先修已知的信息丢失，才能更可靠地识别后两种。

四、近期优化次序应怎样调整

我建议在原计划之前增加一个很小、明确的阶段，并暂缓扩大重构。

第一优先：恢复契约组合后的语义完整性

下一次开工先处理已确认的覆盖问题，让地点投影保留仍然适用的时间类别说明，并保证这些说明来自同一规则来源。

修复范围可以很小，但验证边界应覆盖实际组合：

非地点 schema；
非地点 schema 再经过地点投影；
直接以 locations=true 生成；
最终 provider 请求中的模型可见声明。

如果一份声明可能经过多次投影，还需要避免简单拼接造成说明反复累积。这里要保证的是：当前仍可选择的类别，具有正确且完整的定义。

我不建议把定义再复制进一段地点提示词来补偿。那会增加另一份需要同步的规则副本。

第二优先：用修复后的现有流程重新归因

这一轮对照应尽量保持模型、准入阈值和其他协议不变，区分：

合理的普通活动成本；
未选择的额外等待；
正确与错误的 until 终点；
玩家明确选择的分钟数。

重点记录：错误发生在提案生成、准入判断、执行排序，还是最终交付。

如果修复后普通行动大幅稳定，我会降低大规模活动层重构的近期紧迫性，把持续事件与跨视点连续性提前。 如果仍普遍出现正确行动被成本行阻断、顺序分歧或恢复缺口，再推进活动与成本所有权的收敛，就有更扎实的依据。

这不是要求本轮继续测试；这是下一次恢复工作时的判断顺序。

第三优先：按残余问题推进结构改造

上一轮的活动层建议仍保留，但适合先做必要部分：

统一已完成步骤与剩余步骤的识别；
统一准入、预览和执行所依据的顺序；
明确成本属于哪个活动；
允许真实部分结果交付与恢复。

不必为了修这一个 description 覆盖问题，先重写整个回合协议。
