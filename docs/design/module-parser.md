# 模组解析器设计：做过的策略、踩过的坑、现在的原则

**改模组解析（PDF 读取、骨架/指针索引、释放核验、查书、开场页、cast、地图、任何“读书”的后台通道）之前，必须先读完这份文档；改完要回来更新它。** 同一类问题在这里已经出现过三四次，下一次改动先对照第 4 节和第 5 节。

- 契约：`docs/kernel-rpc.md` §148、§191、§257、§261、§262（精简读取）、§263（指针读取）、§266（翻书模式）。
- 规格：`docs/specs/pointer-module-reading.md`（工单 W01–W12 与状态）。
- 项目文件（owner 线程的完整材料）：`解析历史与根因.md`、`模组解析设计-v2.1.md`。
- 代码入口：`extensions/module/reading-service.ts`（所有读取的总服务）、`lean-skeleton.ts`（指针索引）、`release-check.ts`（释放核验）、`page-mode.ts`（翻书模式）、`source-blocks.ts`（版面块）。

## 1. 现在是怎么工作的（2026-10-24）

一句话：**原文由程序掌握，模型只给指针；指针没覆盖到的地方，KP 自己翻书。**

1. **原文库（程序，0 次模型调用）。** 导入时用 PDF 文字层建版面块（§262.2，`b<页>-<序>-<hash8>`），按文件哈希缓存。任何对原文的引用都是 `SourceRef`（字节范围），程序能精确切回同一段字，切不出就作废。书里的字永远由程序从块里切，不由模型复述。
2. **指针索引（后台一次，整本，单次调用）。** 导入那一刻就开始，整本书在后台并发（8 路）建索引。分节按 token 量自适应：书签起点切节，相邻书签合并到约 6K token 一节，超过就在页边界再切（`skeletonSections`）。所以小模组只有几节，大模组几十节，不存在“一节内容太少”。每节一次不带工具的调用，只输出实体、证据用途、跨场景安排、受保护事实、可释放候选（都是 id 和短句）。答不下就拆成两半，还不行就逐页，逐页仍被拒的页标 `blocked_pages`。每建完一节就写一次部分索引（`<sha>-partial.json`，§266.2），这一节马上能用，不等整本。
3. **释放核验（后台，逐个人物就绪）。** 可释放候选对照受保护事实逐条判 safe/unsafe，结果按行存在 `<sha>-release.json`。不再等整本：每写一次部分索引就跑一轮，一个候选只要“全书所有印着这个人名字的页”都已建好、没被拦，就核验并放出（§266.8）。每条记下它依赖的秘密摘要，秘密不变就不重核。只有 approved 且在本回合范围内的原文才以 `source_N` 发给 KP，KP 选中后才交给作者（§263.5）。
4. **两种模式，按页切换（§266.1）。**
   - **图谱模式**：页所在的节已建好、没被拦。KP 拿到 `book_truth`（书里定好的计划、条件、秘密）、证据窗口和 `source_N`。
   - **翻书模式**：页还没建好、这一节失败、这一页被内容过滤拦了，或者这本书的索引还没开始。KP 用 `lookup kind=source source_mode=pages` 按页码或目录节名翻书。程序切原文（每次最多 3 页，每页 4000 字符），只给 KP，**不开任何读书会话**。`book_truth` 末尾会提醒 KP 索引还没覆盖全书，并附目录前 40 行（§266.5）。
   - 目录由程序生成：PDF 书签取两层；没有书签就用每页第一个版面块的前 80 个字（§266.3）。
5. **精简读取下不开细读（§266.6、§266.10）。** 读书任务在认领时检查：精简细读的页在翻书模式，就直接退回 `cancelled/page_mode`。素材闸门（进场景、对人物检定）只给原文页、不排读书任务。cast 读者在精简读取下永远不跑。
6. **实测基准（Blood Road，111 页，MiniMax M3.1 Flash）。** 建卡期间（约 2.5 分钟）已建好 21/24 节；开桌后 2 分钟整本索引加释放核验完成（第二刀 A 桌，2026-10-24）。第一刀：整本索引加释放约 32–49 万 token，开桌后约 3.5 分钟就绪。

## 3. 循环的根因（不要再绕回去）

1. **图谱同时扮演“索引”和“内容”两个角色，而内容只能靠模型抄出来。** 图谱厚了，模型要把书抄进节点，爆钱；图谱薄了，要内容就得再开读者重读，变慢。现在内容由程序切，索引只放指针。
2. **“取内容”等于“开一个读者会话”。** 细读、呈现件补读、cast、地图、prepare 查书，每条路都是“看页 → 写结构化草稿 → 检查 → 复核”。只要内容是模型写的，复核就省不掉，单价就降不下来。
3. **下游功能硬依赖模型产出的结构，而且没有“还没读到”这个状态。** 产物不在，要么等（慢），要么全读（贵），要么 KP 编（错）。现在“还没读到”就是翻书模式，有明确的退路。

## 4. 反复出现的坑（改之前逐条对照）

1. **“读多了爆 → 缩范围”循环了三次**（两页常驻流 → 只读当前章 → 完全不后台读）。每次缩的都是范围，单价一直没动。要省钱，先降单价（单次调用、指针输出、程序切页），不是缩范围。
2. **“先建一个全书索引”出现了三次。** 索引本身要读完整本，而且索引挂哪页决定后面能不能读到对的内容。挂“提及页”会让 KP 找错页；指针索引的证据要带用途（appearance、description、plan……），按用途取页。
3. **每加一个功能就加一条后台读通道**（地图、cast、页面转写、呈现件补读、页开、prepare、相邻场景预读）。新功能不许自带读者；所有读取都走 `ReadingService`，要能被翻书模式在认领处拦下（§266.6），要记账。
4. **换了读法以后 KP 找不到书里的内容**（§195 prescreen 被丢、§262 骨架挂错页）。每次改读法，都要验证 KP 当回合能拿到原文（证据窗口、`book_truth`、翻书）。
5. **改提示词让缓存全失效。** 索引节的任务里带提示词摘要，改一个字就整本重读。改 `content/setup/lean-skeleton.md` 之类的提示词前，要算清重读成本。
6. **内容过滤。** 开场指引被拒时，只用建卡页（没有就只用开场第一页）再问一次（§266.12，《他们也没想太多》实测 MiniMax 拒了开场页）。索引整节被拒时先拆两半，再逐页；逐页仍被拒的页只拦它自己（`blocked_pages`），只扣住它点名的人物外貌，这些页走翻书模式。不要反复绕过滤烧钱。
7. **分节粒度。** 不按固定页数切，按 token 量合并相邻书签。小模组不能切得太碎（每节有固定提示词开销），大节要在页边界切开，避免单次回复装不下（§263.3 的“答案太长就问两半”）。
8. **单次调用的推理等级。** 表格级别的推理会把输出上限吃满（Blood Road medium：34 次里 8 次撞 8192 输出上限），指针调用固定用 `PI_COC_POINTER_THINKING`（默认 low）。
9. **测完不关进程会继续烧额度。** 进程关掉时读书本来就停；危险的是桌子开着没人玩。现在 20 分钟没有任何活动（开桌、回合提交、准备模组）就停后台读书，交还在途任务，下次有活动再续上（§263.8，`PI_COC_READ_IDLE_MS`）。
10. **懒读时开场图里只有一个场景，没有人物。** 开场落座（§198.3）只认图里的人，于是书印在开场页上的人一个也放不进来，KP 只能把他们写成风景，开场回合反复被拒（A 桌加油站三人）。现在：cast 里还没读的人，只要他的页码落在开场场景引用的页上，就能先落在原文上再入座（§266.7）。以后任何“下游功能只认图里的人或地点”的规则，都要问一句：懒读时图里没有它，这条规则还走得通吗？
11. **回合慢不一定是读书慢。** 2026-10-24 A 桌第 1 回合 13 分钟，读书只占后台；慢在开场回合协议被拒 8 次（单段 thinking 约 1.2 万字）。先看遥测里 `lane: reading` 和回合拒绝，再下结论。

## 5. 原则（不变量）

- 书里的字只由程序从版面块切出来；模型只写 id、闭合枚举和短句（Agents.md 的单次调用判据）。
- 任何读取都不让回合等待。索引没到就翻书，不排读者、不等。
- 翻书模式下不开读书会话；读者重读页面正是之前循环的源头。
- 原文给作者之前必须过释放核验，并且在本回合范围内；KP 读到的原文（翻书、证据窗口、开场页）只给 KP。
- 索引按文件哈希缓存、跨战役共用；战役状态和授权不共用。
- 不用列表或正则判断语义（这段是不是秘密、这个名字是谁）；名字只做归一化拼写匹配。
- 状态要分开说清：索引有没有覆盖、这一节是否失败、这一页是否被拦、原文能不能放出。“索引里没有”不等于“书里没写”。

## 6. 已知问题与待办（2026-10-24）

- **精简读取下不再排细读（§266.10）。** 根因是落座和素材闸门只认“读者发布过的节点”才算就绪，于是 KP 一提人物或地点就排一次细读；其实落座本身已带原文页，计划和证据在 book_truth 里。现在一律不排，`PI_COC_DETAIL_READS=1` 可恢复。人物数值改由机制卡给（§266.11）：书中人物一落在原文上，后台单次调用从印着他名字的页里含数字的块抽属性、派生值、技能，每个数字都必须出现在它引用的那个原文块里，否则丢掉；存在 cast 名册旁边，检定时取用。书里的门槛（比如困难成功才肯听）仍放在 book_truth 里，由 KP 设定难度。
- **W09 读取总账**：有上限、分通道遥测和空闲停止（§263.8）。
- **W11** G01–G30 召回没跑；**W12** 长局和英文书没跑。
- **计划和备选已分开（§266.9）**：索引行带 `type`（默认安排 arrangement / 备选 option / 触发 trigger / 事实 fact），`book_truth` 先给默认安排；跨栏续接的证据块会补上上一栏的半句。改了索引提示词，每本书要重读一次索引。
- **KP 用不用书。** MiniMax KP 很少选用 `source_N`，第一刀也没理会 p13 的拖延计划；翻书模式下 KP 会不会主动翻书，要靠真桌验证。
- **开场落座的 Jev 判断只问图里的人**（cast 里的人只能由 KP 自己入座，§266.7）。
- **翻书一次最多 3 页**，跨节内容要翻多次；目录节名靠拼写匹配，节名含糊时 KP 要改用页码。
