# 0005. 物品身份与使用能力分离

- Status: Accepted direction（2026-09-15）；规格待审阅，尚未实现
- Track: pi-coc，当前 TypeScript 生产内核

## Context

玩家希望能抄起场景中的椅子攻击。现有物品增强可以生成武器定义，但普通物品定义不会投影为武器，既有定义不能换分类，托管实例也不能借普通物品授予路径重新登记。执行资格因此取决于最初登记的分类，而不是动作与物理事实。

用户确认：应根据玩家/NPC行为做语义判断，按用途补齐参数；同一物品同一用法复用已接受参数，不制造另一件「武器版」物品。

## Decision

物品实例保持持续身份；模型解释动作并确定用法，带工具的生成车道补齐缺失的用法参数，内核校验、持久化并按已支持的执行器结算。普通物品与武器不再是实体的互斥执行资格；伤害属于适用用法，存在伤害字段本身不授予行动权限。

接受的用法参数与原始定义分离、不可静默覆盖，实例的所有权、弹药、次数、损坏和文档仍各有唯一状态来源。更换持有人不是重新生成物品或重置状态的理由。

## Alternatives rejected

- **把普通物品改成武器。** 仍把多种用途挤进一个分类，且破坏已接受定义的不变性。
- **复制一件临时武器。** 制造身份、数量与状态分叉，容易借机恢复弹药或清除损坏。
- **只检查 damage 字段。** 缺少使用技能、适用方式与行动授权；无法区分物品事实和本次用法。
- **每次动作重生成参数。** 同一物体的同一种用法会漂移，并增加不必要的模型等待。

## Consequences

需要扩展物品参数准备、接受、投影和战斗读取这一条完整链路，同时兼容已接受的旧定义和存档。咒语知识与实体物品仍是不同概念，不借此合并。

具体范围、待实现契约与验收要求见 [按动作确定物品能力的规格](../specs/action-derived-object-usages.md)。本决定不宣称功能或真桌验收已经完成。
