# Pi CoC 写法参考 v2：让守秘人更会讲、更会接话

**代码参照：**`Leehow/chatrpgv4` 的 `0.9.5a`，固定提交 `6478133878b1fc574f98324401a60bd165d9b5f2`。这不是对未推送工作区的判断。

**本版交付：**48张重写精选卡、12张初始候选、中英分离资产、真实来源研究、TypeScript参考库、两文件提示补丁工具与本地测试。没有直接改GitHub，没有安装到真实应用，也没有声称取得文笔或延迟提升的实测结果。

## 一、这次不是给原方案再加几条免责说明

上一版把“权限受限的改写器”设计得太像整个守秘人，又把选择、诊断、修复一起推向生产。新版改成从现有链路出发的渐进方案：**正向提醒先行，少量范例按需提供，Jev选卡单独验证，文学诊断不进入默认交付门禁。**

48张卡不是把144张缩短翻译，而是按新的比较结构重新撰写。旧144个ID另存迁移清单，区分应归还现有正确性审计的内容与写法参考；没有假定48张与144张一一等价。

最终目标不是“每轮更像小说”，而是“这一轮更能回应玩家”。问门开没开、闲聊、开玩笑、逃命、细看房间、表达难过，应当允许不同的答案形态。安静和朴素不是低质量标签。

## 二、0.9.5a的真实接入位置

实际读取的 `kernel-ts/read/content.ts` 中，`TextGraph.style(language, register, beat, full)` 消费 `content/craft/beat-directives.json` 的 `axis_lines`、`directive_lines`。因此首个补丁直接修改这两组英文文本，保留六个风格轴ID、十一个指令ID、节拍映射与四条floor。

这里还有一个容易漏掉的细节：`full` 模式会取出**所有现有craft-directive节点**。所以不能简单把48张新卡追加成普通图谱指令，否则完整胶囊可能一次把它们全送进去。新卡需要独立的可选参考入口。

`prompts/keeper.md` 已经要求根据 `wants／fears／hides／knows／would_lie_about／ties／toward_party／history` 演人；胶囊代码还有关系、近期发言、承诺与重逢材料。新版利用这些输入，不另造常驻NPC Agent或职业口吻模板。

`mods/narration-audit/auditor.md` 明确允许兼容的新虚构细节，并明确排除文学风格打分。新版保持审计文件不变，继续让它负责可理解性、事实兼容、授权、结果和披露。

## 三、兼容即兴与严格改写是两个权限范围

### 守秘人写作

守秘人仍可创造合理对白、动作表演、普通材质和现场互动。模组不必提前写完每只杯子、每次停顿。**新增并不自动等于越权，兼容也不自动等于无需持久化。**

判断依据是该细节在当前情境中是否有实质后果，而非词面白名单。杯子的温度在吃饭场景中可能只是附带细节，在投毒调查中可能成为证据。人物停顿可以是表演，但不能因此由旁白认证为“心虚”。这不能靠“杯子安全／脚步危险”一类规则处理。

若新增内容成为可使用物品、需要定位或被攻击的人物、必须履行的承诺、获得的线索、新的持续场所、物品转移、时间或机制结果，就继续走现有拥有者与 `apply／resolve` 路径。不要创建一份由写作模块掌管的平行世界状态。

兼容细节一旦交付，也不能下一轮因为“原书没写”就悄悄消失。应通过已有实录与连续性机制保留；需要升级为持久状态时由对应权威处理。

### 受限改写

明确调用的编辑环节，可以被限制为不新增事实，只改变措辞、顺序、焦点和节奏。但这只是该次编辑任务的权限，不是整个守秘人的权限。

卡片的 `elaboration` 专门说明哪些是既定事实、哪些是允许的即兴、哪些不能迁移。某个有附带细节的正例适合守秘人构作，不代表适合直接替换事实严格锁定的原稿。

规则结果、玩家自主选择、线索真相、秘密披露与身份边界不因选卡改变。已有NPC动机影响声线，声线卡不能为了有趣而新增动机。玩家已声明的恐惧可以承接，规则已结算的非自愿效果可以表现，但其他内心回应仍留给玩家。

## 四、卡片改成“比较写法”，而非“错误修理清单”

每张卡都包括共同情境、适用和不适用条件，以及：

| 字段 | 用途 |
|---|---|
| `acceptable` | 合格、可以直接使用的写法，有时它就是最适合的一种 |
| `stronger` | 针对当前情境的编辑改善方向，不是客观分数 |
| `alternative` | 另一种同样成立的表达，避免所有输出同质化 |
| `nearMiss` | 反例，用于理解具体问题；不作为默认旁白输入 |
| `boundaryContext／boundaryText` | 改变上下文后，什么情况可以成立、应该怎样处理 |
| `why／elaboration` | 比较写法，同时说明事实和即兴边界 |

总计48张、8类，每类6张；每卡有四段叙述或对白对照，共192组中英对应例文，另有48组合法边界情境与处理。不要把中英译文算成独立的模型效果样本。

类别为交流目的、人物声线、对白往返、感知与现场、恐怖与未知、句流与节奏、记忆与重访、动作与结果。这是方便人类审阅的分类，不要求每轮强制归入唯一类别。

例如，同样是拒绝交出账本，重点不是为“职员”指定一种腔调，而是使用既有处境：担心追责的人把责任说出来；愿意帮忙的人会划清帮助的边界；坚定敌对的人可以直接威胁。不要把所有人修成温和、无害、含糊的声音。

## 五、真实文学材料怎样进入，而不是装饰性挂名

选读了六部文学作品的具体段落：奥斯汀《傲慢与偏见》开篇对话、柯南·道尔《波希米亚丑闻》开场观察与解释、狄更斯《远大前程》第一章空间铺陈、布莱克伍德《柳树》营地中的主观投射、乔伊斯《死者》后段交谈、曼斯菲尔德《园会》结尾。

另外研究六份跑团材料：《A Time to Harvest》《诅咒之城》《不息的渴望》《Triangle Agency》《The Vault》和CoC守秘人规则书的相关段落。它们分别包括人物扮演钩子、视点命名、循环重现、虚构制度语体、同伴便条与节奏切换。**不是所有模组说明都被当成玩家可读的优美正文。**

研究文件分别记录“原文确实做了什么”“本次怎样理解这种写法”“哪些可以迁移”“哪些不能迁移”。原书短引文只在研究材料中；48张卡的例文全部为原创，并未冒充原书段落。

尤其不能为了迎合规则而误读原作。《柳树》不是纯客观描写，它明确包含主观想象；《死者》也直接描写人物内心。这里借鉴其注意力组织与交流转折，不照搬小说作者对玩家角色的控制权。真实文学案例能支持设计分析，不能证明模型会因此写得更好。

## 六、英文为基础，中文只供审阅

`src/` 与 `runtime/` 是英文实现和资产；中文在 `review/`，双语浏览器也只用于人类审阅。研究说明不属于运行时指令。

实际渲染器只取白名单中的英文正向指导与一个正例，**不序列化整张双语卡**。发布用运行包排除中文审阅文件。静态英文资产的字符检查只检查这批资源，绝不用于玩家输入、角色名字或战役事实。

多语言支持仍由 `play_language` 决定。英文样例提供技法，不是要求把这段英文逐字翻译。生成时应直接使用目标语言的自然句法、停顿与省略方式，不新增一份按语言硬编码的文风表。中文版看起来顺不顺，也不能当作模型跨语言能力的验证结果。

## 七、Jev接现有内循环，但先证明卡片有用

先做正向提醒，再做人工或现有语义路径挑选的少量范例，最后才引入Jev选卡。这样才能区分改进来自提示、样例还是选择器。

Jev复用实际存在的 `runtime/jev/decision-port.ts`、`DecisionBatch`、`TaskLease` 与原有预算及密钥管理。包里没有第二套HTTP客户端，也不会默认联网。选择问题采用真实接口中的 `type: 'choice'` 与 `criteria` 结构。

候选项包含目的、适用条件与例外，始终有 `NONE`。只有确实存在当前卡时才提供 `KEEP_CURRENT`。保持当前写法不是缺省偷懒，而是需当前适用性的合法选项。当前玩家输入和有关人物、场景材料由宿主现有投影提供；不能只看Director节拍。

该组件只返回最多一个可选参考。超时、信息不足、不完整、越界选项或陈旧结果，就回到普通守秘人路径，不为了挽救一次风格建议多调一个LLM。这个回退策略只适用于可选写法，不能复制到必需的授权或规则审核。

`style.reference` 是本版提出的接入槽，并非声称0.9.5a已自动接好。真正实现时要确定实际出站请求的插入点，验证新字段没有在投影、预算或胶囊装配中被剥掉。记录“找到、选中、注入、实际采用”四件事，不拿选中ID当文笔改善证明。

## 八、保持正文生成与审阅的边界

常规路径只考虑成文前的少量参考，不默认加写完后的文学评分。已有正确性审计继续运行，不因追求速度关闭。

原先“Jev判断这段有哪些反例，再挑一个正例”的想法保留为编辑器或后台研究方向。若后续启用，应使用宿主发放的原文片段别名、绑定文本版本、允许无问题／不适用／上下文不足；遗漏型问题指出缺少的信息，不伪造错误原句。Jev选正例不等于它能现场生成任意改稿，真正改写仍由LLM完成。

后台美学建议不得自动变成交付拒绝理由，也不能在已经流式显示后假装玩家没看见，偷偷替换原文。

## 九、预算、缓存与版本

一轮至多一个主要方法，必要时一个短正例。12张只是初始候选池，不是12条常驻指令。完整卡库不每轮枚举，反例不默认进入旁白请求。

附加上下文按宿主明确分配的字节预算处理：放不下正例就整块不放；连方法都放不下就不加卡。字节预算不是token估计，更不是正文字数配额。不得为了样例挤掉本来必需的事实。

宿主仍负责输入版本、当前世界线、人物关系与知识、材料版本、模型配置、任务取消和真实read-set。参考库提供资产哈希与调用者版本绑定检查，但不能代替宿主验证世界状态。Jev概率也不是已校准的正确率，不提供凭空决定的万能阈值。

基础声线可以保持，回合参考不应无理由每轮重选。但场景、目的、说话者、知识状态变化时，应重新判断适用性。返回场景可以复用材料，不能复用旧结论；不加机械冷却表或随机轮换。

## 十、两处实际发现的旧约束没有被悄悄绕过

现有开场提示仍规定最多一句房间描写、每段发言最多一个动作；另有提示称重复台词会被拒绝。前者可能是特定开场的防冗长手段，不应误报成每轮配额。后者若确有运行时守卫，也不能只靠新提示许可“有效回扣”就算解决。

这两处已列入独立兼容性任务，自动补丁不删除它们。先定位实现与验收，保留新手定向、避免空转的原目标，再决定如何放宽。需要逐字重复的某些边界例，目前是写法教材，不是声称已经能通过生产守卫。

## 十一、怎样证明有用

四组依次比较：A现有版本，B只有正向提醒，C在B上增加少量精选范例，D用Jev挑选同一套范例。固定实际模型、提示版本、输入材料、结算结果和缓存条件，避免同时改三四个因素。

先从真实历史回合做配对盲读，保留必要前文、人物状态、事实、授权与结算结果；只拿孤立一句话不足以标注上下文问题。允许平手、都不合适；分别评估接话、人物可辨识性、可理解性、气氛匹配、连续性与玩家自由，不用“更文艺”替代所有维度。

样本须包含直接问答、笑话、敌意拒绝、丧失后的安静、检定失败、安全房间、长观察、重访、重复请求、循环和不同语言。留出未由教材卡片派生的隐藏测试集。文字盲评之后，再经真实UI逐回合跑团，观察交互是否真的更好。

性能记录用户输入到首字、正式交付、可再输入时间，实际provider往返、tokens、重试、放弃选卡以及范例物件串入剧情。不能因为本地选择函数很快就宣称端到端提速。
