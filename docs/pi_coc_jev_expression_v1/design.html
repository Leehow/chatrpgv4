Pi CoC × Jev：可控表达与正反例诊断系统

设计版本：1.0 · 日期：2026-09-23 · 包标识：pi-coc-expression-cards-v1

交付状态：设计、原创种子卡库及离线参考工具；不是已接入 Pi 的生产功能，也不是已经验证的 Jev 中文文笔评测器。

本设计把“选择表达方法”“识别具体表达缺陷”“找到可借鉴的正例”结构化，让 LLM 集中完成当前事实的语言实现。卡库包括 144 张卡、144 组同上下文正反例、144 个防误判边界例；即 288 段主对照文本与 144 段边界文本。所有故事片段均为本次原创虚构示例，不是从商业模组或规则书抽取的片段。

1. 结论与范围

系统采用 事实胶囊 → 表达计划 → 一次成文 → 按需诊断与有限修复。Jev 做有类型的选择和判断，宿主处理权限、引用、版本、预算与发布，LLM 生成和改写自然语言。

用户所说的“Jev 评估当前文字的反例并给出正例”，在本设计中准确拆成四项：

  1. 判断当前稿件是否符合某张反例卡定义的失误，而不是判断“是否出现了反例里的词”。
  2. 从宿主预先切分的原文片段中选择证据；代码根据片段 ID 提取原文，不让模型凭空引用。
  3. 返回一个或多个适用的正例/修复策略 ID；代码从卡库展开正例及其适用条件。
  4. 需要把正例的方法应用到当前剧情时，由 LLM 在不改变事实的前提下改写。

检索正例 ≠ 生成当前稿件的改写。给出一个编号 ≠ 证明其对应材料已经进入模型请求。

本设计覆盖文字层与其运行时边界，不重写规则引擎、整个记忆系统或导演系统。表达层可以提出“需要重新核实”的问题，但不直接掷骰、扣资源、改变时间、创建线索、修改人物立场或决定玩家行为。

1.1 依据与未验证范围

项目依据为附件《ChatRPG 跨版本优化与重构验收总册》中的 ARC、NPC、TXT、CTX 相关契约，以及《评估方案设计建议》关于分维度、证据、盲比和真人校准的要求。[P1][P2]

本次没有读取或运行当前 GitHub 0.9.4a 源码。后文模块名、接口、目录与生命周期节点都是建议接口，不能当作现有仓库真实符号。本包只把可迁移契约落成实施规格；编码 Agent 必须在目标提交上完成实际接线映射。

1.2 外部能力与本设计推断分开

按核查时的 TypeSafe 官方文档，Jev 提供 Choice、Score、Noul，不提供开放式文本生成；同一请求中的问题针对同一 state 独立评估。Choice 的选项键和描述会进入模型，但 questions 的键不会被模型看见。[S1][S2][S5]

因此，“让 Jev 当中文表达诊断器”是本设计提出的应用方法，不是厂商文档已经证明的能力效果。中文语体、跨轮重复、假设/引述边界、秘密暗示与人物声线都要在真实样本上验证。

2. 必须守住的六条边界

边界 权威拥有者 表达系统可以做什么 不可以做什么
规则与资源 单一规则执行与提交路径 实现收据含义 靠文采增加伤害、缴械、移动等效果
世界事实 模组/事件/状态拥有者 选择已授权事实的顺序与措辞 新增道具、身份、因果、过去或未来
认识与披露 接收者知识投影 使用当前接收者可知信息 以比喻暗示未公开秘密
玩家控制权 玩家授权与明确规则效果 承接已声明感受、动作与合法非自愿效果 代写未声明情绪、信任、计划或自愿行为
人物表达 NPC 当前知识/动机/关系与 voice 为已决定内容选择措辞 从职业词推断性格，擅自改立场
发布与恢复 Pi 宿主交付状态机 保存草稿、审阅、修订版本 把事后删除当成撤销玩家知情

不是所有语言创造都是新增事实。句法、停顿、音韵、信息焦点和明确的非字面修辞可以变化；但任何会影响“谁存在、在哪里、做过什么、能做什么、知道什么、为什么发生”的内容，都要受事实授权约束。

2.1 避免把正文变成字段复述

允许的自由分为三层：

纯语言自由：同义表达、句法、节奏、段落、衔接。通常不新增状态。

可选表面表现：NPC 的停顿、音量、普通姿态等，只能在宿主给定 surface_permissions 内展开。它们也可能被玩家当线索，所以默认不把“眼神闪躲”“藏起手”“手在颤抖”当无害装饰。

新叙事事实：新的声音、天气、物件、伤势、举动、可疑痕迹，先回到高层决策/事实流程，获得授权并纳入胶囊，再成文。不能靠“只是增加气氛”越过这一步。

4. “数值化”具体指什么

采用 card_id + numeric_id + version + 描述，不把一个数字误当知识。

  • PEC-HOR-001：稳定可读主键；改文件路径不改语义身份。
  • 5001：宿主紧凑索引；不是语义向量，也不要求数值相近的卡含义相近。
  • card_version：版本锁；含义改变须升版本，拆卡新增 ID 并保留历史迁移关系。
  • retrieval_text：用于语义召回的描述，包含目的、条件与失败模式。

表达参数采用有描述的离散档位，例如 brief / balanced / expansive、direct / restrained / lyrical。篇幅是软目标；必要事实优先。参数控制的是表达行为，不是“好文笔 0.9”这一虚假精度。

4.1 稳定层与增量层

基础旁白声线 + 场景表现目标 + NPC 固定 voice + 本轮局部策略。

基础层变化少；切换到追逐时减少旁枝，回到休息时恢复舒缓。不必每轮重选一切。KEEP_CURRENT、KEEP_DRAFT、NONE 都是正式选项。没有合适技法时直接说清事实，不强行调用卡库。

近期已用技法只是候选排序的软特征，不是禁用冷却表。线索复现、人物口令与主题兑现可以合法重复。

5. 卡片资产模型

本包的 12 个家族，每类 12 张：FCT 事实、AGY 自主性、CLR 清晰度、SEN 感官、HOR 恐怖、LYR 美感、DIA 对白、VOI 声线、PAC 节奏、MEM 连续性、RUL 规则实现、OUT 输出与诊断。

卡片同时保存正面目标与反面判据，不做仅有禁止事项的清单。每张卡的最小内容：

字段 用途
身份、版本、家族、标签 索引、路由与版本治理
applicability 本卡何时有意义；自然语言条件不硬编成词表
failure_mode 单一可解释失误，不把多个互不相关维度揉成总分
desired_behavior 应该如何表达
scope / channels 句、轮、对话、跨轮窗口；玩家正文与工程诊断分开
required_context 需要事实、授权、历史、voice、规则收据的哪些材料
contrast 同一上下文的反例与正例，以及改动原因
boundary 看似类似但合法或不适用的案例，用来防止误报
repair 修复拥有者、修改目标、保护内容、可引用正例
activation integrity、style 或 diagnostic_meta；不能只按审美召回全部选择
review / provenance 原创种子、人工复核状态、是否进入生产校准

三种“正负”不要混用： 日常所说反例，是违反卡片目标的坏写法；分类器中把 VIOLATION 当 positive class 时，合法边界例反而是 negative class。数据里始终使用明确标签，不用 positive=good 这种容易反转的缩写。

5.1 本包卡片的适用边界

144 组主例均是目标卡的教学对照；不保证正例是唯一好写法，也不保证某段正例在任意其它上下文中都优秀。边界例判断也只针对目标卡：一个合法引用可能包含难听的台词，但不等于它违反“不能让叙述者代替玩家下判断”。

OUT-008 至 OUT-012 面向诊断/运行策略审阅，不作为玩家旁白风格范例。它们的正例可能是工程处理建议，绝不能照抄进剧情正文。

所有卡的人工状态初始为 pending；自动检查只能验证结构、引用、覆盖与示例标签的形式一致性，不能代替真人认可。

6. 数据结构与权威事实胶囊

建议在真实 Pi 请求前生成 FactCapsule。不要把整个守秘人世界摘要交给一个只负责公开文字的模型，再祈祷它不泄露。

{
  "turn_ref": "宿主绑定，不要求模型回填",
  "revision": 18,
  "recipient": "player-a",
  "public_facts": [
    {"id":"F1","text":"窗台有三道新鲜抓痕","source_ref":"事件/来源绑定"},
    {"id":"F2","text":"床底发出一次短响，随后恢复安静","source_ref":"事件/来源绑定"}
  ],
  "required_fact_ids": ["F1","F2"],
  "epistemic_limits": ["声源尚未确认"],
  "player_authorizations": ["观察窗台"],
  "rule_effects": [],
  "surface_permissions": [],
  "npc_voice_refs": [],
  "public_history": [],
  "scope_complete": true
}

每个字段都由现有拥有者投影。示例里的 source_ref 是说明性占位，不是现有仓库的 API。事实 ID 用于收据与验证，不强制正文出现 ID。

草稿需要能说明哪个接收者、哪个 revision、哪个事实胶囊以及哪个表达计划产生。纯审美诊断通常只拿公开胶囊。需要验证是否透露守秘信息的内部检查，在单独私有通道拿最小必要私有材料，不能把这些材料再传给公开正文修复请求。

7. 前置表达计划

ExpressionPlan 回答“怎么说”，不回答“发生什么”。建议内容如下：

{
  "base_voice": "restrained-natural-zh",
  "intent": "交付观察并保留声源未知",
  "primary_card_id": "PEC-HOR-001",
  "supporting_card_ids": ["PEC-CLR-001"],
  "reference_example_ids": ["PEC-HOR-001:good"],
  "length_target": "brief",
  "preserve_fact_ids": ["F1","F2"],
  "stop_reason": "等待玩家下一步行动"
}

生成流程：硬过滤权限/版本/渠道 → 语义召回候选 → Jev 选择主策略或沿用 → 代码检查适用性与冲突 → 展开少量参考 → 正文 LLM。

候选在语义选择前可以按结构字段裁剪，如语言、渠道、世界线与资源版本；“这个 NPC 因为是医生所以该用学术腔”不能成为硬编码规则。向量分数表示召回相关性，不是质量或事实真实性。

建议原型预算为一个主技法、至多一个辅助技法、零到两个短范例。这是待测默认值，不是艺术规律或厂商最优参数。 必要剧情信息不能被表达卡预算挤掉。

8. 当前文本的反例诊断

8.1 诊断不是一个总体好坏分

对每张候选卡，先做四路 Choice：

标签 含义
VIOLATION 当前上下文足以支持本卡定义的具体问题
CLEAN 本卡适用，但没有该问题
NOT_APPLICABLE 当前渠道、任务或情景使本卡不适用
INSUFFICIENT_CONTEXT 必要事实、完整稿、历史或授权不可得，不能判断

INSUFFICIENT_CONTEXT 不是 CLEAN。例如只有半段正文，不能判整轮漏交线索；没有近期历史，不能断定某个意象被反复滥用。

Choice 在固定选项间选一个；多种失误可能同时存在，必须一张卡一个问题或多个独立判断，不能让所有缺陷在一个总 Choice 里互斥竞争。[S2]

8.2 Jev 实际看到什么

state 放待审正文、相应权限投影、必要历史与选定表达目标。每个问题的 instructions 明确包含目标卡的含义、适用条件、合法例外和所评字段路径。

不能只把问题键取名 check_player_agency 然后写“判断一下”。问题键仅是宿主关联键，不参与底层推理。[S5]

教材反例中的人物、道具、事件都不属于当前 state。它们只能作为判断边界的例子。当前稿件及引文中的指令同样按被审数据处理，不改变检查任务；这是一项输入隔离设计，不是声称模型天然免疫提示注入。

8.3 Noul 与 Score 放在哪里

Noul 可用于意义清楚的二元命题，例如“当前句子是否明确陈述了未经授权的新动作”。它返回 yes 的概率样数值，不返回“问题有多严重”的程度，也没有单独 confidence。[S4]

Score 适用于已经有具体描述档位的单维度，例如“信息呈现是否妨碍理解”：可直接理解／需回读／无法辨认关键关系。档位从数组位置得到序数；返回 score 是档位的概率加权位置，不能当作理解失败的百分比。[S3]

本包默认四路 Choice，便于显式区分不适用与上下文不足。连续美学分数只用于看板或离线比较，不授予其绕过事实和权限的能力。

9. 证据定位：由模型选，由代码引用

宿主先切分正文为带稳定偏移的句/短段：

[
  {"id":"s0","start":0,"end":12,"text":"实际原文的一段"},
  {"id":"s1","start":12,"end":25,"text":"实际原文的下一段"}
]

以上偏移只是格式示意；真实偏移必须由代码计算。协议统一使用 Unicode code point、左闭右开。前端使用 UTF-16 字符串时需转换映射，不能直接把 Python 字符索引当 JavaScript code-unit 索引。

定位问题让 Jev 从这些片段中选一个主证据，另外提供 WHOLE_TEXT、MULTIPLE、OMISSION、NO_LOCAL_EVIDENCE。返回片段 ID 后，代码验证 ID 归属、revision 与 hash，再用偏移切出原文。原文引用真实，不等于判断必然正确。

遗漏型错误没有“错误原句”。 必须指向本轮必须交付的事实，以及完整稿件的未覆盖判定；不要为了让报告好看而编造一个不存在的反例片段。跨轮重复应引用多个真实 turn/span，单轮稿件不能伪造跨轮证据。

单个 Choice 目前最多 255 选项，因此长文按窗口分批，不把整场战报所有句子塞进一次定位选择；窗口边界、覆盖完整性和未评估范围必须记录。[S2][S5]

10. 正例选择与修复合同

反例命中后有三种“给正例”方式：

同卡正例：直接展开目标卡的 :good，最少增加调用。

相关卡候选：从相同修复目的的几张卡中选更合适方法。只有需要进一步区分时才增加 Jev 请求。

当前文本改写：把诊断、原文、当前公开事实与获选方法交给 LLM；这一步不是 Jev 的文本生成能力。

正例必须展示原场景条件，并标记 transfer_mode=technique_only。默认只迁移方法与尺度，不迁移人物、物件、地名、因果、台词承诺和事实数量。

10.1 修复合同示意

{
  "diagnostic_ids": ["宿主生成的诊断引用"],
  "target_spans": ["s1"],
  "goal": "删除未确认的怪物存在与意图，保留声响",
  "required_fact_ids": ["F1","F2"],
  "reference_examples": ["PEC-FCT-001:good"],
  "allow_new_facts": false,
  "max_attempts": 1,
  "result_channel": "unpublished_draft"
}

LLM 输出完整修订段或宿主支持的结构补丁。为避免错位编辑，补丁必须带原稿版本和 hash；多条重叠失误先合并，不让三个卡串行改同一句三次。若待补的是遗漏事实而非坏句，修改范围可以是整轮，但仍只允许使用已授权事实。

10.2 不是所有问题都交给写手修

纯句法、冗余与风格不适配交给 narrator；事实胶囊冲突交事实拥有者；规则收据矛盾交规则/投影层；私有信息混入请求交权限投影层；玩家授权缺失回到相应 pending 流程。

已结算资源和事件绝不因为重新生成正文而再次执行。修复是新的 narration revision，不是新 turn 的规则重放。

11. Pi 内循环集成

建议生命周期如下；名字不是现有 Pi 符号。

OBSERVE
  → 高层行动/导演决策（需要时）
  → AUTHORIZE / RESOLVE / COMMIT（现有权威路径）
  → PROJECT_PUBLIC_FACTS
  → PLAN_EXPRESSION（Jev或复用有效计划）
  → GENERATE_NARRATION（LLM）
  → 按交付模式进行既有正确性检查与可选诊断
  → PUBLISH
  → 更新表达历史与审计收据

这不是外面再套一个循环追问 Pi “写得好吗”。运行时拥有表达计划和交付检查；正文 LLM 不为了领取卡片反复调用工具。只有遇到未知高层决策才回到已有决策节点。

11.1 内循环接口建议

prepareExpression(capsule, previousStyle, budget) 返回计划； compileNarratorInput(capsule, plan) 返回真实请求与注入收据； diagnoseDraft(draft, capsule, policy) 返回类型化诊断； compileRepair(draft, diagnostics, capsule) 返回补丁任务或退回拥有者； publishNarration(draftRevision, expectedStateRevision) 负责交付幂等。

禁止在每个模块各自保存一份世界状态。使用已有场景、记忆和事件接口，卡库只存表达知识。前端审阅面板与生产 KP 共享同一资产编译器，避免“编辑器有效，游戏里没加载”。[P1: NPC-04]

12. 四种运行模式

模式 前置选择 当前稿件诊断 是否同步重写 适用
plan_only 开 无新增风格诊断 否 先验证前置选择的独立收益
shadow_audit 可开 交付后进行，不能追回披露 否 默认诊断试运行与样本积累
guarded_repair 开 发布前完成 最多一次且经校准策略允许 风险敏感交付与经过验证的修复
editor_review 可选 完整稿件/历史审阅 人工确认或指定批量操作 开发、战报编辑、卡库完善

这里的“无新增风格诊断”不等于停用项目已有的权限和正确性防线。表达实验不得以关闭原有保护获得速度优势。

12.1 关于默认模式

本包的自动修复默认关闭，calibration_status=unvalidated。这是因为卡库和模型尚未进行真实语义验证，而不是认为任何诊断都不值得做。先用影子模式检查误报与遗漏，再按问题家族启用有限同步修复。

13. 流式输出与不可逆披露

完整缓冲：稿件检查通过后才发布。可以在前台显示不含剧情的处理状态，但不把“处理中”当作故事首字。首字延迟增加，需要单独测量。

分段缓冲：一个完整语义段检查后再发布下一段。已经发布的前段不能无痕重写；跨段指代、遗漏和主题检查未必能在首段完成。它不是等价于全稿检查的零泄密方案。

直接流式 + 影子审阅：最快交付路径之一，但诊断只改善后续行为，不能声称阻止已经流出的秘密。

产品须显式选择模式。安全关键正文不得用事后修订当成发布前保护。即使完整缓冲，语义检查也会误判；输入最小化、权限投影和确定性授权仍是根本防线。

14. 串行调用预算与依赖

同一 Jev 请求中的问题独立；“第2问使用第1问刚得到的答案”不会自动发生。[S1]

可以对已经确定的候选卡推测性并行询问：是否违反、若违反哪个现有片段最能说明、若需修复哪种预置策略适合。宿主只消费被接受诊断对应的定位/策略。代价是更多问题与更长说明，并非免费。

若必须根据第一轮诊断动态检索新的正例，则第二轮 Jev 请求是实实在在的新增串行等待。文档和性能日志都要把它算进去。

建议起步：前置计划0—1次Jev；影子诊断1次；条件修复至多1次LLM，再验证一次。没有必要每轮固定运行完整流水线。对每个模式记录实际调用数，不能拿拓扑图的“一个节点”冒充“一次请求”。

真实收益公式：

节省的决策/检索/重写往返 − 新增选择/审阅/范例输入/修复开销。

厂商对批量判断的低延迟描述不是本应用的端到端结果；中文输入长度、候选说明、网络、队列和正文长度都必须在真实环境测。[S1][S2]

15. 置信度、校准与弃权

Choice/Score 的 confidence 来自其概率分布形状，并非独立的事实正确率；集中分布也可能自信地判断错误。Noul没有独立confidence。数值需要结合目标数据校准。[S3][S4][S6]

本设计不预设“0.9就安全”。保留完整 probabilities、confidence、模型实际版本、question digest 与state digest。先在人工复核集上为问题家族建立误报/漏报曲线，再选择动作阈值。

两道阈值可以分别控制“进入审阅”和“允许自动修复”。高严重性但低确定性的问题不是悄悄放行，也不是直接改写：在严格交付模式暂缓相关交付、补取已有材料或回到拥有者；在影子模式仅记为未决，不能追认其为安全。

状态为 NOT_APPLICABLE 或缺完整输入时不产生“严重度为零”的假数据。保持有效分母，报告 coverage 与 abstention rate。

16. 缓存、分支与失效

卡正文是版本化静态资产，可缓存；当前事实和诊断不能只按“场景ID相同”复用。

表达计划缓存键至少包含：卡包版本、基础声线、语言、场景版本、相关NPC voice版本、规则表现模式、已授权表达目标、接收者/分支。诊断缓存另含原稿hash、事实胶囊revision、必要历史digest与question版本。

A→B→A时保留A的静态参考，但重核A当前事实、知识和时间。回滚/回环按世界线与epoch隔离；不能把旧线索、新世界状态和另一角色记忆混成一个便宜摘要。文本改一个字，旧span也须按新稿重算或显式失效。

17. 超时、取消与失败路径

情况 正确行为
Jev超时，纯风格计划 沿用已有效基础声线或直接表达，不宣称已完成评分
Jev超时，影子审阅 记未评估，后续重试受预算限制，不阻塞新回合
必需正确性验证不可用 按既有安全交付策略处理；不能因为风格服务宕机绕过权威防线
返回非法ID/缺问题/类型不符 拒绝该答卷，不从相似字符串猜一个ID
玩家取消或新revision到来 丢弃迟到计划/诊断/改写；记录取消，不污染下一轮
修复后仍有阻断问题 停止循环，返回拥有者或使用宿主已经验证的最小交付；不默认原稿安全
卡库不可用 保留事实与规则交付能力；风格参考不是可玩性的单点依赖

退化路径里的最小交付也必须来自公开权威材料。不能临时拼一个“看起来安全”的故事，同时漏掉规则结果或必须交付的线索。

18. 数据、权限与运维

将正文、私有胶囊发往外部服务意味着数据离开本地。部署前根据实际服务条款、项目资料权限与玩家约定决定哪些材料可发送；本包没有核定任何服务端保留或训练政策，不作“绝不存储”之类承诺。

API key只在后端；HTML卡库浏览器不发送网络请求，也不收集密钥。日志分公开叙述与内部审计；脱敏后才作为错误样本归档。原始模组文本不自动并入公共卡库。

参考HTTP工具默认不发请求。只有显式调用--live才发送examples/current_draft.json指定内容，可能产生费用。正式产品需要限流、请求字节预算、总deadline、取消、观察指标与密钥管理。

19. 测试：不能用卡库自证有效

19.1 本包自带的432条是什么

每张卡导出反例 VIOLATION、正例 CLEAN、边界例 CLEAN 或 NOT_APPLICABLE。这些是开放的种子教学/回归样本，不是隐藏测试集，不能用来宣布泛化准确率。

同一正反例共用上下文；边界例显式提供不同上下文。评测应检查上下文变化是否真的改变判定，而不是只测关键词。所有标签均为本次编写的预期，尚未有独立人工标注一致性。

19.2 需要另外建立的真实验证集

从实际KP输出中收集问题与合格文本，由至少两位审阅者独立标注并记录分歧。覆盖新模组、新NPC、新场景、长回合、多轮重复、规则强制效果、引文、否定、假设及用户主动要求的语体切换。

按战役/场景/同源改写组划分调试集、校准集与保留集。不能让同一片段的改写在两边。保留集不进入卡库、不供候选召回、不在prompt里作为范例。卡包版本改变后保留旧评估清单。

19.3 分层指标

层次 指标
召回 已知错误卡召回率、候选量、必要完整性检查是否被裁掉
诊断 每卡/每家族precision与recall、误报、弃权率、上下文翻转一致性
证据 span是否真实、定位是否恰当、遗漏型证据是否基于完整稿
正例 适用性、跨场景实体污染、是否误把工程正例注入旁白
修复 新增事实率、必要事实覆盖、玩家自主性、改写引入新错误率
文笔 盲比偏好、平手率、可读性、声线辨识、跨轮重复与自然度
性能 真正首个剧情字符、全稿交付、可再次输入、p50/p95、token、调用数、取消与失败

不把所有维度合成可以互相抵消的总分。没有新增事实不等于有趣；更好看也不能抵消泄密。[P2]

19.4 对照实验

A现有正文路径；B只加前置标签；C标签加少量正例；D=C加影子诊断；E=C加校准后的条件修复。对每组固定模型、事实、行动、规则结果、可见性、基础正确性防线和相近输出预算。不要拿“不开审核的流式”与“完整缓冲审核”比较后归因于文风选择器。

配对单轮测试定位差异；固定行动轨迹隔离KP变化；完整AI玩家游戏看总体体验；真人盲读与实际游玩验证主观收益。长团统计以战役/玩家簇计算不确定性，不把同一战役几百句话当作完全独立样本。

20. 必须包含的破坏性回归

定向删除一次真实prompt注入，测试应失败；篡改一个示例ID应被拒绝；将旧revision诊断回填新稿应失败；把另一分支的记忆混入应被权限检查捕获；把范例里的钟楼迁到无钟楼场景应计为新事实。

另外测试：纯文本不出现伤害数字但意义正确应通过；规范“被”字句应保留；原始证物错字不得静默修改；规则授权的非自愿效果不误判；完全安全的场景不因缺恐怖元素被强迫增加怪物；真正有意义的重复线索不被压缩；窗口不完整时弃权；已有好稿选择KEEP_DRAFT；取消后不得迟到发布。

这些是待在生产链执行的验收要求，不因本包存在种子数据而自动PASS。

21. 实施顺序与交付门

阶段A：资产与协议。 导入144张卡，确认Schema与版本；生成一份只含选择摘要的索引、一份诊断索引与完整卡资产。冻结旧基线。默认自动修复关闭。

阶段B：前置垂直接线。 用一个真实场景贯穿胶囊→Jev选择→卡片展开→真实正文请求→输出。捕获请求，证明不是只写了一个没人读取的style文件。

阶段C：影子诊断。 对真实稿件产生类别、原文证据与正例卡，前端只给开发者看。收集错误、平手与反误判，不偷偷改玩家已收到的历史。

阶段D：有限修复。 先选人工标注和验证充分的问题家族。明确同步代价、最大一次改写、重新验证、失败回退。问题根因在上游时退回上游，不反复润色。

阶段E：跨轮与分支。 加入声线连续、A→B→A、回环、多人、取消与恢复。独立测试边界和性能。

阶段F：发布判定。 真实错误集、保留集、盲评与端到端证据全部齐备后，再决定启用范围。不能用“144张卡”“432个样本”或本地单元测试数当作效果认证。

22. 实际出站请求与采用收据

每轮至少记录：运行commit、卡包manifest hash、模型请求别名及实际model、基础prompt版本、胶囊revision与digest、候选卡、选中卡、拒绝原因、展开的示例ID、最终注入位置与digest、诊断答卷、补丁次数、交付模式、最终稿hash。

区分五件事：found搜到、eligible条件允许、selected选择、injected真进请求、effect_evaluated输出效果已检查。最后一项是语义/人工评估结果，不是哈希相等就能证明的“采用”。

23. 交付包文件与使用边界

cards/cards.jsonl 是完整资产；cards/selection_index.jsonl 是摘要；cards/examples.jsonl 是带上下文的独立示例；cards/cards.md 是可审阅全文；card_browser.html 提供离线搜索。

runtime/reference.py 负责类型化请求编译、返回结构检查、可选HTTP调用、原文片段引用及修复合同编译。它没有实现完整Pi、语义召回、正确性权威或生产发布门禁。tests/seed_cases.jsonl是从卡片导出的开放样本；tests/test_reference.py只测试参考工具的确定性行为。

最后应形成的能力不是“每句话必须套卡”，而是：有足够好的默认表达；知道什么时候不该改；发现具体问题时能拿出真实证据、合适正例和不越权的修复路径。

当前文本诊断与正例修复演示

以下是人工编写的期望流程示例，没有调用 Jev，也不是其真实答卷。

1. 当前权威材料

窗台有三道新鲜抓痕。床底发出一次短响，随后恢复安静，声源未知。玩家只要求查看窗台，没有声明害怕或后退，没有强制情绪与移动效果。本轮必须交付抓痕和声响。

2. 待审文本

窗台上有三道新鲜抓痕。床底的怪物正在等你。恐惧攥住你的心，你立刻退到了走廊里。

3. 期望定位

卡 原文证据 问题 正例参考
PEC-FCT-001 床底的怪物正在等你。 将未知声源变成确定怪物与意图 PEC-FCT-001:good
PEC-AGY-001 恐惧攥住你的心，你立刻退到了走廊里。 未经玩家声明代写情绪 PEC-AGY-001:good
PEC-AGY-003 恐惧攥住你的心，你立刻退到了走廊里。 未获授权执行后退与转移位置 PEC-AGY-003:good

同一段原文被两张卡命中，不应改两次。另需完整性检查：本轮应该交付的是一次声响；删除怪物句后必须恢复这项已授权观察，而不是单纯删到只剩抓痕。

4. 取出的正例不是可直接替换的当前事实

PEC-AGY-003的种子正例涉及信封和地址。它只能展示“在新行动前停下”的方法，不能将信封塞进床底场景。

正例引用展开时，同时给出原上下文和transfer_mode=technique_only。若引用会引入不必要的干扰，可仅将技法说明放进改写请求，不提供全文例子。

5. 一次修复后的候选稿

窗台上有三道新鲜抓痕。床底响了一下，随后又静了。声源还无法确认。

这是本次编写的修复候选，不是唯一好写法。它保留两项观察，删除未经确认的实体/意图与玩家动作。表达仍可在更直接或更抒情之间调整，但不能改变这些边界。

6. 同一原句为什么可能不再是反例

新增合法上下文：玩家已经看到床底的怪物，意图经过允许的高层决策公开；玩家自己声明“我害怕了，立刻退到走廊”；移动已经完成。

在这个新上下文中，上述“怪物”“害怕”“退到走廊”不再构成原来三张卡的未经授权错误。是否好读可以另评，但不能继续套用旧诊断。

7. 本包如何运行

runtime/reference.py会从原文计算真实code-point偏移，编译Choice问题，并写出请求与绑定文件。默认只有dry run。需要用户明确提供密钥并添加--live才会发送远程请求。

即使收到VIOLATION，报告也标成model_flagged_unverified，并给出静态卡片说明，不假装Jev生成了长篇解释。报告不授予发布权限，也不自动修改角色状态。

交给编码 Agent 的实施任务书

任务：将本包设计接入目标 Pi CoC 内循环，保留当前规则、事实、知识投影、授权与交付权威。先完成一个真实垂直切片，不增加一个独立常驻写作Agent，也不把卡库全量永久塞进prompt。

按顺序实施

A. 验证卡片Schema和引用；导入完整卡、摘要索引、独立范例与manifest。生产运行时不依赖author_cards.py。

B. 通过现有投影接口构建事实胶囊。正文服务没有世界状态写权限。解析ID用确定性代码；判断自然语言意图或适用性不得退化成关键词路由。

C. 接入plan_only。建立候选选择、NONE/KEEP_CURRENT、卡片展开、实际请求注入与收据；默认一个主技法，辅助与范例都有预算。

D. 接入shadow_audit。诊断当前文字，返回每卡四路结果与真实原文定位；默认不要自动改写，也不要将开发者诊断显示给玩家。

E. 建立真实人工标注与校准。独立比较前置选择、范例和审阅的贡献；分别统计误报、遗漏、弃权和延迟。

F. 对已验证问题家族启用有限修复。合并重叠span；一次改写后重新验证；根因在规则、权限、授权或数据冲突时返回拥有者。

G. 测试完整缓冲/分段/直接流式的不同语义，以及取消、恢复、分支与A→B→A。不要声称事后审阅能撤销已披露秘密。
