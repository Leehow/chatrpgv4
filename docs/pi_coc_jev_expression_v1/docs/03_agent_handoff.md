# 交给编码 Agent 的实施任务书

任务：将本包设计接入目标 Pi CoC 内循环，保留当前规则、事实、知识投影、授权与交付权威。先完成一个真实垂直切片，不增加一个独立常驻写作Agent，也不把卡库全量永久塞进prompt。

## 开始前必须填写

| 核对项 | 目标仓库证据 |
|---|---|
| 目标commit与可启动基线 | 待读取当前仓库后填写 |
| 回合内状态机与正文调用点 | 待定位真实符号与路径 |
| 规则收据的唯一拥有者 | 待确认 |
| 公开知识投影拥有者 | 待确认 |
| NPC voice现有生产链 | 待捕获真实请求 |
| 取消、revision、交付幂等接口 | 待核验 |
| Jev配置、实际模型、超时与请求预算 | 待核验 |
| 现有同步正确性/隐私检查 | 待列出，实验中不得无记录关闭 |

本文不声称以上任何功能已经存在或正确。不要从旧评估文档中的Python文件名推断当前TypeScript树。

## 按顺序实施

A. 验证卡片Schema和引用；导入完整卡、摘要索引、独立范例与manifest。生产运行时不依赖`author_cards.py`。

B. 通过现有投影接口构建事实胶囊。正文服务没有世界状态写权限。解析ID用确定性代码；判断自然语言意图或适用性不得退化成关键词路由。

C. 接入`plan_only`。建立候选选择、NONE/KEEP_CURRENT、卡片展开、实际请求注入与收据；默认一个主技法，辅助与范例都有预算。

D. 接入`shadow_audit`。诊断当前文字，返回每卡四路结果与真实原文定位；默认不要自动改写，也不要将开发者诊断显示给玩家。

E. 建立真实人工标注与校准。独立比较前置选择、范例和审阅的贡献；分别统计误报、遗漏、弃权和延迟。

F. 对已验证问题家族启用有限修复。合并重叠span；一次改写后重新验证；根因在规则、权限、授权或数据冲突时返回拥有者。

G. 测试完整缓冲/分段/直接流式的不同语义，以及取消、恢复、分支与A→B→A。不要声称事后审阅能撤销已披露秘密。

## 完成定义

提交必须包含真实源码映射、出站请求证据、版本/权限绑定、接口测试、定向破坏测试、固定行动轨迹和失败样本。每一项标注“已实现待验证/已验证/未实现/不适用”，不得只报测试总数。

交付要回答：哪些LLM往返真的被删去？新增Jev/审阅往返是多少？哪种错误减少了，哪种误报增加了？文字是否更自然？规则与玩家控制权是否保持？
