The wire probe reports no observer errors in the final run.

Raw stream inspection rules out one candidate explanation: current MiniMax
`message_start` reports zero input/output and no cache field; `message_delta`
reports the final counters. The host is not overwriting a large start-frame
cache count with128 in this sample. It also has no128-token cache-cap setting.
The historical reports therefore cannot be dismissed as a local display cap.

[MiniMax's current documentation](https://platform.minimax.io/docs/api-reference/text-prompt-caching)
describes automatic prefix caching and confirms that Messages `input_tokens`
excludes cached input. [Anthropic's caching documentation](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
describes explicit prefix writes and bounded lookback. The latter's breakpoint
placement is not proof that MiniMax retained or served a KV prefix. Matching
client hashes alone cannot establish server residency, eviction or routing.
No server eviction/sharding explanation has been verified for the historical
two128-token requests; those remain an open investigation, with a complete wire
and raw-usage probe retained for the next reproduction.
